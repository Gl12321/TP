# Проверки запуска и инструментов

Этот набор защищает поведение вокруг приложения: повторный запуск сохраняет секреты, неверные настройки останавливаются до внешних действий, повреждённые веса и архивы не принимаются, команды проверок не продолжают работу после ошибки. Внешние процессы и загрузки подменены; рабочие данные и модели не нужны.

## Состав

| Файл | Контракт |
| --- | --- |
| [test_startup.py](test_startup.py) | Проверка хоста без изменения данных, повторный запуск, режим без AI, остановка при ошибке подготовки и целостность файлов модели |
| [test_config.py](test_config.py) | Профили, безопасные пути и отклонение ошибочных настроек |
| [test_backup.py](test_backup.py) | Состав архива и ограничения восстановления |
| [test_checks.py](test_checks.py) | Обязательная отдельная БД и остановка последовательности при ошибке |
| [test_demo.py](test_demo.py) | Защита подготовки demo: предусловия, сохранность состояния и границы очистки |

Проверка кода подготовки demo не запускает демонстрационный сервер и не использует его постоянные данные. Самостоятельные [демонстрационные сценарии](../docs/demo/README.md) предназначены для просмотра продукта; они не являются частью этой команды.

Прикладные проверки находятся рядом с компонентами: [backend](../backend/tests/README.md), [SQL-агент](../packages/sql_agent/tests/README.md), [frontend](../frontend/tests/README.md). Это компактные проверки основных контрактов, а не исчерпывающий набор на каждую функцию.

## Запуск

В подготовленном окружении с [requirements-dev.txt](../requirements-dev.txt), из корня проекта:

```text
python tools/check.py runtime
```

Для одного файла:

```text
python -m pytest tests/test_startup.py -q
```

Общая автономная проверка Python, frontend и TypeScript:

```text
python tools/check.py quick
```

Она не требует серверов, Docker и ML-зависимостей. Прямой `python -m pytest -q` использует [pytest.ini](../pytest.ini) и включает PostgreSQL-интеграцию, если задан `RAZBOR_TEST_DATABASE_URL`. Для неё нужен отдельный локальный тестовый кластер. Браузер получает только `APP_UI_CREDENTIALS` отдельной установки; демонстрационные реквизиты не используются.

Все режимы, команды Windows/Linux и границы результата описаны в [руководстве проверок](../docs/development/testing.md). Проверки готового HTTP-приложения и настоящей модели — в [tools](../tools/README.md).

## Изменение набора

Добавляйте правило в существующий сценарий, когда оно использует те же предусловия. Проверяйте наблюдаемое последствие: сохранённый секрет, отказ запуска, неперезаписанную БД или код ошибки. Не дублируйте внутренние шаги реализации ради числа проверок.

В общий размер тестового кода входят фикстуры, вспомогательные проверки и браузерный сценарий. Перенос проверок в другую директорию не уменьшает этот размер. Успешный автономный набор не заменяет миграции настоящей PostgreSQL, браузер или известный ответ готовой модели; эти границы запускаются явно.
