# Проверки границ и сценариев

Тесты должны подтверждать наблюдаемое поведение: пользователь видит только свою область, отменённое задание не публикует поздний ответ, ошибочный запуск не теряет данные, а SQL не читает запрещённые поля. Для этих свойств не требуется каждый раз загружать многогигабайтную модель.

Корневой каталог отвечает за подготовку запуска. Предметные проверки находятся рядом с backend, frontend и самостоятельным SQL-пакетом. Старые проверки Streamlit, импорта SQLite, LangGraph и Chroma удалены вместе с заменённой реализацией; проверки языка SQL, промптов, контекста, памяти и результатов перенесены в пакет.

## Наборы

| Набор | Что проверяет |
| --- | --- |
| [test_startup.py](test_startup.py) | Порядок Compose-команд, сохранение секретов и данных, блокировку одновременных запусков, отказ при ошибке, целостность файлов моделей |
| [test_config.py](test_config.py) | Выбор Qwen3.5, раннюю проверку параметров, безопасные пути и закреплённые файлы |
| [backend/tests](../backend/tests/README.md) | Сессии, роли, изоляцию, приглашения, обсуждения, задания, миграции и ограничения SQL |
| [SQL-пакет](../packages/sql_agent/tests/README.md) | Грамматику, AST, промпты, поиск, продолжения, исправления и отмену |
| [frontend](../frontend/README.md) | Формы, состояния интерфейса, точность значений и браузерные сценарии |
| [HTTP smoke](../tools/README.md) | Совместную работу собранного приложения на новом изолированном развёртывании |

Из корня проекта:

```text
python -m pip install -r requirements-dev.txt
python -m pytest
python -m build packages/sql_agent --wheel
```

Для frontend из его каталога:

```text
npm ci
npm test
npm run build
```

## Настоящая PostgreSQL

[Интеграционный набор](../backend/tests/test_postgres_integration.py) включается переменной `RAZBOR_TEST_DATABASE_URL`, указывающей на отдельный локальный тестовый кластер PostgreSQL. Нужна административная роль с правами создания БД и ролей. Тест создаёт случайную БД `razbor_it_*` и роль чтения, выполняет миграции и удаляет только созданные им объекты. Не используйте для этого рабочий кластер.

```text
python -m pytest backend/tests/test_postgres_integration.py -q
```

Без переменной эти проверки явно пропускаются. Проверяются настоящий SQL после серверного ограничения области, точные десятичные значения, права чтения, отмена, таймауты, ограничения результата, внешние ключи и аренда задания. SQLite в автономных API-тестах не доказывает поведение PostgreSQL.

## Как понимать результат

Тест с управляемым генератором доказывает контракт и управление заданием, а не качество SQL настоящей LLM. Нативная компиляция GBNF проверяет совместимость языка с движком без загрузки весов. Браузерный тест проверяет реальные действия, но не заменяет измерение памяти при генерации.

[CI](../.github/workflows/verify.yml) разделяет Python на Windows/Linux, frontend, PostgreSQL и Docker smoke. Настроенный workflow ещё не является выполненным прогоном. Фактические результаты и ограничения фиксируются в [VALIDATION.md](../docs/VALIDATION.md).
