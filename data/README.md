# Рабочие данные и сохраняемое состояние

Приложение должно сохранять результаты и совместную работу при перезапуске, смене модели и обновлении кода. Для этого исходные данные бизнеса, состояние самого приложения и восстанавливаемый кеш поиска хранятся отдельно. Кеш можно построить заново; отчёт или историю обсуждения — только восстановить из сохранённой БД.

## Где что хранится

| Данные | Место | Назначение |
| --- | --- | --- |
| Бизнес-операции | Внешний PostgreSQL клиента | Источник чтения для показателей и вопросов; приложение не копирует всю базу к себе |
| Пространства, участники, подключения, планы, задания, результаты и обсуждения | Прикладная PostgreSQL в томе `postgres_data` | Постоянное состояние продукта |
| Описания каталога и поисковые векторы | Том `agent_data`, в Compose `/app/data/indexes` | Повторное использование разрешённого контекста поиска |
| Веса и файлы моделей | Корневой `models` | Локальная генерация и поиск; точные версии закреплены YAML |
| Пароли развёртывания и ключ приложения | `.runtime/compose.env` либо выбранный `--env-file` | Доступ к прикладной БД и расшифровка сохранённых подключений |

Локальная папка `data` может использоваться при нативном запуске как место кеша. Её содержимое исключено из Git, кроме этого README. Путь индекса задаёт `APP_INDEX_DIR`; реальный Docker-кеш находится в именованном томе, а не обязательно в этой папке хоста.

## Как это используется

[Поиск агента](../packages/sql_agent/src/sql_agent/retrieval/README.md) строит индекс из разрешённых описаний таблиц. Он проверяет версию и отпечаток представления, поэтому несовместимый кеш перестраивается. Индекс не заменяет исходную базу и не хранит историю результатов пользователя.

[Backend](../backend/README.md) записывает предметное состояние в свою БД. Сохранённая таблица отчёта остаётся снимком конкретного выполнения; новый расчёт обращается к текущим данным внешнего источника и создаёт новую запись. Данные источника резервирует его владелец отдельно от приложения.

`APP_SECRET_KEY` нужен для расшифровки паролей источников. Прикладная БД без соответствующего ключа недостаточна для восстановления подключений. Штатный [инструмент резервирования](../tools/backup.py) включает ключ, dump и конфигурацию в один архив; такой архив содержит секреты.

## Остановка, перенос и очистка

`python run.py --stop` сохраняет именованные тома, модели и секреты. Повторный запуск подключается к ним и применяет недостающие миграции. Пересоздание контейнеров само по себе не является сбросом данных.

Кеш допустимо удалять после остановки worker, чтобы следующий запуск построил его заново. Удаление тома PostgreSQL уничтожает рабочее состояние, а удаление env-файла может потерять ключ подключений. Поэтому кеш, служебную БД и секреты не объединяют одной операцией очистки.

Порядок переноса и проверки копии — в [резервном копировании](../docs/operations/backup.md). Размещение томов — в [Docker](../docs/operations/docker.md), параметры путей и секретов — в [конфигурации](../docs/operations/configuration.md).
