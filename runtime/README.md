# Подготовка рабочего окружения

Одинаковая команда должна запускать приложение и на новой машине, и после обычной остановки. Этот слой приводит окружение к ожидаемому состоянию: проверяет выбранную конфигурацию, подготавливает локальные файлы моделей и создаёт прикладную роль PostgreSQL. Сам продукт после подготовки работает с готовыми ресурсами.

Пользовательская точка входа — [run.py](../run.py). Она выполняется на хосте через Python 3.11+ и управляет Docker Compose. Модули `runtime` исполняются в подготовительных контейнерах; приложение и библиотека агента не скачивают модели при импорте.

Python и Docker устанавливаются отдельно по [инструкции с нуля](../docs/operations/install.md). `run.py --check` проверяет интерпретатор, Compose и Linux Engine без сборки, файлов секретов и скачиваний. Это проверка хоста; сами модели и приложение проверяются последующими этапами запуска.

## Разделение ответственности

| Файл | Назначение |
| --- | --- |
| [config.py](config.py) | Прочитать YAML, проверить параметры и собрать настройки выбранного профиля |
| [models.py](models.py) | Проверить закреплённые файлы моделей, получить недостающие и сохранить отметку готовности |
| [prepare.py](prepare.py) | Выполнить подготовку, показать каталог моделей или только проверить конфигурацию |
| [database.py](database.py) | Создать отдельную прикладную БД и роль с ограниченными полномочиями |

Модели выбираются из [config.yaml](../config.yaml): Qwen3.5 4B/9B/27B и два вспомогательных набора поиска. Загружается только выбранная основная модель. Для каждого файла закреплены версия репозитория и контрольная сумма. Подтверждённые неизменившиеся файлы используются повторно; смена профиля не удаляет другие веса с диска и не загружает их одновременно в память.

Для файлов сохраняется атомарная отметка готовности. При её отсутствии или изменении файла выполняется проверка размера/контрольной суммы. Кратковременная сетевая ошибка допускает ограниченные повторы загрузки. Ошибка проверки прекращает подготовку и не выдаётся за готовность модели.

`database.py` получает административные реквизиты только на время подготовки PostgreSQL. API и worker работают с отдельной обычной ролью приложения; она не получает права суперпользователя, создания БД и ролей. Миграции схемы выполняет [bootstrap backend](../backend/app/bootstrap.py), а не модуль загрузки моделей.

## Последовательность запуска

Launcher сначала проверяет Python, Compose и доступный Linux Engine. После успешной проверки блокирует второй запуск, сохраняет секреты, проверяет YAML, собирает образы и проверяет прикладные настройки. Затем останавливает прежний worker, запускает БД, подготавливает роль и применяет миграции. После готовности API в терминале появляются адрес интерфейса и код первого входа. Подготовка весов и старт worker идут следующим этапом; открыть браузер можно до их завершения.

Общий запуск не удаляет данные при ошибке подготовки. После исправления причины та же команда использует сохранённое окружение. API обслуживает доступные обычные операции и сохранённые результаты, пока обработка новых вопросов ещё не готова.

```text
python run.py --check
python run.py --model qwen3.5-9b
python run.py --list-models
python run.py --without-ai
python run.py --stop
```

В Linux может использоваться `python3`; флаги одинаковы. `--list-models` выводит каталог без загрузки весов, но работает через подготовительный контейнер и потому требует Docker. `--without-ai` пропускает загрузку моделей и запуск worker; пересчёт отчётов тоже требует worker и в этом режиме недоступен. `--stop` сохраняет тома, файлы моделей и секреты.

В Windows после установки Python используйте `py -3.12` вместо `python`; имя `python` может указывать на Microsoft Store alias. Все примеры предполагают выбранный рабочий интерпретатор.

## Настройки и связи

Секреты по умолчанию находятся в `.runtime/compose.env`, другой готовый файл выбирается `--env-file`. Его нельзя подменять новыми ключами при обычном повторном запуске: сохранённые подключения зашифрованы прежним `APP_SECRET_KEY`. Обычные параметры и разрешённые хосты источников хранятся в YAML.

[Backend](../backend/README.md) владеет пользователями, подключениями и заданиями. [SQL-пакет](../packages/sql_agent/README.md) получает локальные пути и настройки и выполняет запрос. [Docker Compose](../docker-compose.yml) связывает подготовительные сервисы с API, worker и БД.

Компоненты, зависимости и ожидаемое поведение описаны в [эксплуатации](../docs/operations/README.md), контейнеры — в [Docker](../docs/operations/docker.md), параметры — в [конфигурации](../docs/operations/configuration.md). Проверки запуска находятся в [tests](../tests/README.md): они подменяют внешние команды и не заменяют проверку настоящего развёртывания.
