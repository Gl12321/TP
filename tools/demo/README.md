# Демонстрационные сценарии

Этот инструмент собирает отдельное локальное приложение для ручного знакомства с продуктом. Сценарий `network` показывает готовую сеть и взаимодействие ролей, `onboarding` — первое знакомство владельца с пустым пространством. Оба используют обычные API, базу и интерфейс; отдельной реализации продуктовых правил в demo нет.

Полный порядок запуска, локальный PostgreSQL и маршруты по интерфейсу описаны в [руководстве demo](../../docs/demo/README.md). Инструмент не является набором тестов и не зависит от `backend/tests`, pytest или браузерного runner.

На новой машине следуйте [подготовке demo с нуля](../../docs/demo/README.md#подготовка-demo-с-нуля): установка Python и Node, venv, сборка frontend, запуск PostgreSQL и проверка перед заполнением. Инструмент не устанавливает эти зависимости и не запускает PostgreSQL.

## Устройство

| Модуль | Ответственность |
| --- | --- |
| [__main__.py](__main__.py) | CLI, выбор сценария, последовательность подготовки, миграции и запуск Uvicorn |
| [state.py](state.py) | Пути каждого сценария, постоянные секреты, аккаунты, проверка согласованности и свободного порта |
| [database.py](database.py) | Создание выделенной прикладной БД и обычной роли, проверка сохранённого пространства |
| [source.py](source.py) | Самостоятельный источник учебной сети: таблицы продаж и точек, данные, роль чтения и исходные определения |
| [seed.py](seed.py) | Создание пространства, участников и деловых сценариев через HTTP API, сверка реального результата аналитики |
| [compose.yml](compose.yml) | Необязательный отдельный PostgreSQL 16 для demo, проект `razbor-demo`, порт `55434` |

Сначала проверяются frontend и HTTP-порт. Для нового сценария инструмент получает административный DSN из `RAZBOR_DEMO_DATABASE_URL`, записывает намерение подготовки и создаёт отдельную прикладную БД. Сценарий `network` дополнительно получает отдельный источник PostgreSQL и роль только для чтения. После миграций наполнение выполняется через тот же API, который вызывает браузер.

`seed.py` использует HTTP-клиент внутри процесса: авторизация, CSRF, создание участников, настройки источника и бизнес-действия проходят настоящие обработчики. Он не заполняет прикладные таблицы обходными SQL-вставками. `source.py` записывает SQL-данные только в созданную учебную БД источника.

После подготовки запускается обычный backend с собранным `frontend/dist`. Модели и worker не запускаются. Успех подготовки означает, что учебные ресурсы созданы; он не является проверкой качества LLM или полноценным прогоном тестов.

## Сценарии и состояние

| Сценарий | Начальное содержимое | HTTP-порт | Каталог |
| --- | --- | --- | --- |
| `network` | Шесть ролей, две точки, источник, показатели, планы, разборы, адресные вопросы, ответы и техническое обращение | `8766` | `.runtime/demo` |
| `onboarding` | Директор — владелец пустого пространства | `8767` | `.runtime/demo-onboarding` |

Каждый каталог содержит `state.json`, `accounts.json` и блокировку `launch.lock`; у готовой сети также есть `source.json`. Ранее созданный `credentials.json` не нужен новым сценариям. Состояние и пароли сохраняются между запусками; административный пароль в эти файлы не переносится.

`RAZBOR_DEMO_DATABASE_URL` нужен только при первичном создании конкретного сценария. Повторный запуск использует сохранённую обычную роль приложения. Источник читается собственной ограниченной ролью. Произвольные удалённые серверы для подготовки не принимаются.

При ошибке подготовка пытается удалить только подтверждённо созданные ею ресурсы. Если создание или очистку нельзя однозначно подтвердить, файлы сохраняются для диагностики. Имена, сервер и соответствие ресурсов проверяются до очистки. Автоматического сброса готовой демонстрации нет.

## Команды

Все команды выполняются из корня репозитория в окружении с `requirements.txt` и базовым пакетом `sql_agent`:

```text
python -m tools.demo --check
python -m tools.demo
python -m tools.demo --scenario onboarding
```

Они запускают HTTP-сервер до `Ctrl+C`. Остальные действия:

```text
python -m tools.demo --scenario network --accounts
python -m tools.demo --scenario onboarding --accounts
python -m tools.demo --scenario network --prepare-only
python -m tools.demo --scenario onboarding --prepare-only
```

`--accounts` явно показывает локальные реквизиты без запуска сервера. `--prepare-only` создаёт или проверяет сценарий и завершает работу. `--port` выбирает адрес только при первой подготовке: менять порт существующего состояния этой командой нельзя.

`--check` проверяет импорты, frontend, свободный HTTP-порт и подключение PostgreSQL без миграций и изменения состояния. При первой подготовке дополнительно проверяет права создания БД и ролей. В этих командах `python` — интерпретатор окружения с установленным `requirements.txt`, а не заглушка Windows Store.

Установка пакетов, сборка frontend, запуск Docker и скачивание образов не выполняются автоматически. Подробные команды подготовки находятся в [руководстве](../../docs/demo/README.md).

## Как изменять demo

- Новые исходные продажи, периоды и ожидаемые значения меняются в `source.py`. Данные должны согласовываться с формулой показателя, планами и текстами обсуждений.
- Последовательность взаимодействия ролей меняется в `seed.py`. Используйте публичные API и реальные разрешения участников; не создавайте фиктивные успешные расчёты агента.
- Новый самостоятельный сценарий требует отдельных путей состояния, стартового порта и явного начального содержимого. Он не должен зависеть от существования другой демонстрации.
- Изменения заполнения применяются при создании нового состояния. Они не перезаписывают уже созданную сеть и пользовательские правки.

Сами права, расчёты и действия реализованы в [backend](../../backend/README.md), интерфейс — во [frontend](../../frontend/README.md). Исправления продукта вносятся туда; demo лишь связывает их в полезный ручной маршрут.
