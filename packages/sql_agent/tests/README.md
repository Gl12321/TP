# Проверки SQL-ядра

Проверки защищают форму запросов, границы данных и поведение агента при ошибке. Они выполняются без весов модели и не выдаются за оценку качества LLM.

`test_pipeline.py` проводит заранее заданные ответы генератора через настоящий валидатор и исполнение на небольших SQLite-таблицах: проверяет итоговые суммы JOIN, сохранение основания диалога, отказ от выполнения при смене доступа, исправления, уточнения, отмену и общий дедлайн. SQLite используется только для переносимых SQL-примеров; особенности PostgreSQL проверяются интеграционными тестами приложения.

`test_sql_grammar.py` проверяет допустимые и запрещённые предложения GBNF; при наличии доступной нативной библиотеки дополнительно компилирует грамматику llama.cpp без загрузки модели. Блокировка библиотеки политикой Windows отмечается как пропуск, а не успешная нативная проверка. `test_sql_validation.py` проверяет ограничения AST и раскрытие `*` только в доступные колонки.

`test_retrieval.py` проверяет раздельные префиксы E5, размерность векторов, смену клиента/версии/модели, восстановление повреждённого индекса, широкие таблицы и сохранение связующих таблиц при ограниченном контексте. Тесты адаптера llama.cpp отдельно проверяют шаблон, остановку, ошибки и очистку ресурсов.

`test_native_adapters.py` использует настоящие CPU-тензоры PyTorch: проверяет исключение padding из среднего, L2-нормализацию и выполнение без вычисления градиентов. В базовой установке без PyTorch этот тест пропускается; веса моделей ему не нужны.

После установки пакета запуск из корня репозитория: `python -m unittest discover -s packages/sql_agent/tests`. Реальная приёмка выбранных GGUF дополнительно требует контрольных русских вопросов, эталонных результатов PostgreSQL и измерения памяти всего приложения.
