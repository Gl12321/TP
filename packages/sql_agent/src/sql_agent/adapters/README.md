# Локальное выполнение моделей

Адаптеры соединяют независимый SQL-алгоритм с конкретными библиотеками inference. Основная модель составляет запрос, encoder ищет таблицы, reranker уточняет порядок кандидатов. Эти ресурсы загружает worker, чтобы обычные HTTP-запросы не создавали дополнительные копии весов.

## Как распределены обязанности

| Файл | Ответственность |
| --- | --- |
| [llama.py](llama.py) | GGUF, шаблон, токенизация, ограниченная генерация и выгрузка основной модели |
| [embedding.py](embedding.py) | CPU encoder, префиксы E5, усреднение токенов и нормализация векторов |
| [reranker.py](reranker.py) | Оценка пары «вопрос — фрагмент таблицы» и сортировка кандидатов |
| [concurrency.py](concurrency.py) | Выполнение блокирующей работы в потоке и ожидание её завершения при отмене |
| [memory.py](memory.py) | Доступная RAM с учётом ограничений cgroup на Linux |
| [runtime.py](runtime.py) | Разрешение локального пути вспомогательной модели |

Базовый импорт `sql_agent` не загружает эти модели. Зависимости локального исполнения находятся в группе `local` [pyproject.toml](../../../pyproject.toml). Точные модели и параметры задаёт конфигурация приложения, а не код адаптера.

## Генератор и управление ресурсами

`LLMClient` получает локальный `model_path` и параметры llama.cpp. Он использует встроенный шаблон GGUF, отключает thinking и проверяет, что шаблон действительно подготовил начало ответа. Подсчёт токенов и генерация используют одинаковое представление промпта. Управляющие токены внутри данных вопроса отклоняются.

Перед загрузкой проверяются размер весов, рабочий резерв и свободная RAM для приложения. Во время генерации проверка доступной памяти повторяется. Локальный дедлайн не может быть позже общего дедлайна вопроса.

Нативный callback прерывает CPU-вычисление при отмене, истечении времени или исчерпании резерва памяти, включая первоначальную обработку промпта. Следующий запрос получает модель после завершения нативного вызова и сброса прерванного состояния. `close()` также ожидает освобождения генератора.

Проверка памяти не предсказывает каждое нативное выделение. `runtime_memory_mb` — резерв, а не измеренный размер состояния модели. Увеличение контекста требует отдельного расчёта ресурсов; размер GGUF не равен полной памяти worker.

## Поисковые модели

Encoder выполняется напрямую через Transformers и CPU PyTorch. Для E5 применяются `query: ` и `passage: `, masked mean по attention mask и L2-нормализация. Padding не должен менять представление документа. Параметры, revision и способ сериализации входят в fingerprint индекса.

Reranker ожидает один logit на пару текстов. Для таблицы берётся максимальная оценка её фрагментов. Sigmoid сохраняет порядок, но не превращает оценку в вероятность правильного ответа. По умолчанию порог отсечения отсутствует.

Обе модели работают пакетами в режиме inference без градиентов. Проверка отмены выполняется между пакетами. Размеры пакетов влияют на время и память; значение задаётся конфигурацией приложения.

## Подготовка и связи

Encoder и reranker открываются с `local_files_only=True` и `trust_remote_code=False`. Адаптеры не скачивают веса и не заменяют модель при ошибке. Предварительную проверку файлов выполняет [runtime/models.py](../../../../../runtime/models.py).

Выбор профиля и размеры файлов описаны в [models](../../../../../models/README.md), работа индекса — в [retrieval](../retrieval/README.md), установка и изменение адаптеров — в [руководстве разработчика](../../../../../docs/development/sql-agent.md).
