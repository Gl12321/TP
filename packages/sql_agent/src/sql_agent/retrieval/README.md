# Поиск нужных данных

Пользователь называет показатель, город или товар, а модель должна получить конкретные поля и связи. Здесь разрешённый каталог превращается в небольшой набор таблиц для ответа. В поиск не передаются данные другого клиента или поля вне выданного профиля.

[semantic.py](semantic.py) сравнивает вектор вопроса с векторами описаний таблиц. Широкая таблица делится на группы колонок, поэтому полезное поле в конце схемы не исчезает из-за ограничения длины encoder. Оценка таблицы берётся по наиболее подходящему фрагменту. [serializer.py](serializer.py) создаёт эти описания.

Для небольших каталогов используется точное сравнение векторов. Отдельная векторная БД здесь не требуется. Ключ индекса включает namespace клиента/источника/профиля, версию, содержимое схемы и fingerprint модели поиска. При любом изменении строится другой индекс. На диске сохраняются только векторы с проверяемым ключом; запись атомарная, повреждение вызывает пересоздание. Кэш в памяти ограничен числом каталогов, размер каталога — числом фрагментов.

[context.py](context.py) добавляет кратчайшие пути по внешним ключам и проверяет размер промпта через переданную функцию подсчёта токенов. Таблица с необходимыми связями добавляется одной группой. Таблицы выбранного основания диалога обязательны; невозможность вместить их возвращается пользователю явной ошибкой.

Модели предоставляет [adapters](../adapters/README.md), актуальный разрешённый каталог — приложение через `AllowedCatalog`. Поиск помогает найти данные, но не определяет разрешения и финансовый смысл показателя.
