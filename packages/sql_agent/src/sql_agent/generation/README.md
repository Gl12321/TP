# Перевод вопроса в SQL

Генерация соединяет деловой вопрос с технической структурой данных. Модель должна выразить нужный расчёт доступным SQL либо вернуть определённый код уточнения или отказа. Ответом этого модуля не являются рекомендации или придуманные значения показателей.

## Как устроены сообщения

[prompts.py](prompts.py) хранит системные правила и собирает отдельный JSON с вопросом, таблицами, определениями показателей, выбранными условиями и основанием продолжения. Пользовательский текст и описание таблиц не становятся системными инструкциями.

При исправлении к исходной задаче добавляются предыдущий SQL и структурированная ошибка. Основание продолжения диалога передаётся отдельно: это выбранный успешный расчёт, а не неудачная попытка. Текущие фильтры имеют приоритет над старыми; конфликт периода в тексте вопроса с явно выбранными датами требует уточнения.

[template.py](template.py) применяет шаблон из GGUF в sandbox Jinja2, с `enable_thinking=False`. Адаптер llama.cpp использует тот же шаблон для подсчёта токенов и генерации. Управляющие токены внутри данных отклоняются, чтобы вопрос не создавал новые роли чата.

## Правила изменения

Промпт должен оставаться согласованным с [грамматикой](../sql/grammar/README.md) и [AST-проверкой](../sql/validation.py). Нельзя просить модель вызвать функцию, которую последующие уровни запрещают.

При доработке нужно сохранять исходные фильтры, определения показателей, единицы и кратность строк. JOIN с таблицей на стороне «многие» способен завысить SUM и COUNT; SELECT DISTINCT не является универсальным исправлением. Для календарных периодов задаются полуоткрытые границы, для долей — десятичная арифметика и защита делителя.

SQL либо коды протокола являются полными ответами. Markdown, объяснение и рассуждение нарушают контракт. Если нужен новый код уточнения, он добавляется согласованно в `GenerationRefusal`, грамматику, правила промпта и обработку [pipeline](../pipeline/README.md).

Конкретный шаблон зависит от модели. Совместимость шаблона с движком и качество SQL проверяются отдельно; успешный разбор Jinja не доказывает правильность расчёта.
