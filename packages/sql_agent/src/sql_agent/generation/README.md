# Перевод вопроса в SQL

Генерация получает деловой вопрос, доступную структуру данных и согласованные определения показателей. Её результат — SQL либо короткий код причины, по которой нужен другой вопрос или уточнение. Она не пишет рекомендации и не заменяет расчёт объяснительным текстом.

[prompts.py](prompts.py) разделяет системные правила, вопрос, каталог, определения показателей и выбранное основание диалога. Данные сериализуются в JSON. Неудачный SQL и ошибка добавляются отдельным обменом сообщений, сохраняя исходную цель вопроса.

[template.py](template.py) применяет встроенный шаблон выбранного GGUF с отключёнными рассуждениями. Llama-адаптер считает токены тем же шаблоном, который используется при генерации. Управляющие токены внутри пользовательских данных отклоняются, чтобы текст вопроса не создавал новые роли чата.

GBNF начинает действовать с первого сгенерированного токена. Совместимость шаблона и конкретной сборки llama.cpp проверяется отдельно от качества SQL. Формат ответа определяет [грамматика](../sql/grammar/README.md), а жизненным циклом генерации владеет [pipeline](../pipeline/README.md).
