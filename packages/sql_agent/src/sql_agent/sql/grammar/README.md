# Язык аналитических запросов

Грамматика помогает модели составлять запросы для повседневной аналитики: выбрать строки, связать таблицы, посчитать показатели и сгруппировать результат. Она ограничивает выдачу с первого токена, поэтому запись в БД и неизвестные имена не относятся к допустимому ответу генератора.

## Как устроен язык

[builder.py](builder.py) подставляет таблицы и колонки текущего разрешённого контекста. Источники получают канонические псевдонимы `t0`, `t1` по отсортированным именам. SQL-идентификаторы экранируются отдельно от строк GBNF; сравнение имён учитывает точное написание.

| Ресурс | Содержание |
| --- | --- |
| [lexical.gbnf](lexical.gbnf) | Литералы, строки, числа, пробелы и имена результата |
| [expressions.gbnf](expressions.gbnf) | Поля, арифметика, CASE, предикаты, агрегаты и даты |
| [select.gbnf](select.gbnf) | SELECT, JOIN, фильтрация, группировка, сортировка и границы выдачи |

GBNF-файлы включены в wheel. Строитель читает ресурсы рядом с модулем, поэтому библиотека не зависит от рабочей директории запуска.

## Поддерживаемые операции

| Группа | Возможности |
| --- | --- |
| Выборка | SELECT, DISTINCT, звёздочка, именованные выражения |
| Соединение | JOIN/INNER JOIN и LEFT JOIN с явным ON |
| Условия | Сравнения, AND/OR/NOT, IS NULL/TRUE/FALSE, LIKE/ILIKE, BETWEEN, IN с непустым списком литералов |
| Расчёт | `+ - * / %`, CASE WHEN, COALESCE, NULLIF |
| Агрегаты | COUNT, SUM, AVG, MIN, MAX; COUNT(*) и COUNT(DISTINCT одно_выражение) |
| Группировка | GROUP BY и HAVING |
| Даты | CURRENT_DATE, DATE/TIMESTAMP/INTERVAL-литералы, DATE_TRUNC и EXTRACT |
| Выдача | ORDER BY с ASC/DESC и NULLS FIRST/LAST, LIMIT/OFFSET |

Агрегаты не используются в WHERE, JOIN ON и GROUP BY. Вложенные агрегаты запрещены. Выходной псевдоним разрешён как целое выражение ORDER BY; GROUP BY и HAVING повторяют исходное выражение.

CTE, подзапросы, UNION, оконные функции, self-join, другие виды JOIN, произвольные функции и CAST не входят в язык. DATE и TIMESTAMP здесь являются формами литерала, а не разрешением на произвольное приведение типов.

При включённом протоколе генератор может вернуть целиком один из ответов: `INSUFFICIENT_CONTEXT`, `UNSUPPORTED_QUERY`, `CLARIFY_PERIOD`, `CLARIFY_METRIC`. К коду нельзя дописать объяснение или SELECT; такой ответ не исполняется в БД.

## Почему требуется следующая проверка

Грамматика знает допустимые имена и форму, но не все правила области видимости и группировки. Например, она может разрешить колонку из контекста, чей источник модель не добавила в FROM/JOIN. Это отклоняет [AST-валидатор](../validation.py).

Изменение языка требует согласованных правок GBNF, валидатора, [промпта](../../generation/prompts.py) и ограничения источников в бэкенде. Особенно это касается конструкций с вложенными областями видимости. Для каждого расширения нужны допустимые и запрещённые примеры, а также проверка результата в PostgreSQL.
