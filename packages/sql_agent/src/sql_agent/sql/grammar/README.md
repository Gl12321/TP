# Ограниченный язык аналитики

Грамматика направляет модель к запросам, которые нужны для обычной аналитики: выбрать строки, объединить связанные таблицы, посчитать показатели и сгруппировать результат. Это сокращает число синтаксических ошибок и запрещает запись в БД уже во время генерации.

[builder.py](builder.py) подставляет только таблицы и колонки текущего разрешённого контекста. Канонические псевдонимы `t0`, `t1` назначаются по отсортированным именам источников. SQL-идентификаторы экранируются отдельно от строк GBNF.

| Ресурс | Содержание |
| --- | --- |
| [lexical.gbnf](lexical.gbnf) | Строки, числа, пробелы и литералы |
| [expressions.gbnf](expressions.gbnf) | Поля, арифметика, CASE, предикаты, агрегаты и даты |
| [select.gbnf](select.gbnf) | SELECT, JOIN, фильтрация, группировка, сортировка и ограничение строк |

Поддерживаются INNER/LEFT JOIN, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT/OFFSET, COUNT/SUM/AVG/MIN/MAX, COUNT DISTINCT, CASE, COALESCE, NULLIF, DATE_TRUNC и EXTRACT. CTE, подзапросы, оконные функции, UNION и self-join не входят в язык. Грамматика не была расширена ими при переносе пакета.

При включённом протоколе разрешены четыре самостоятельных ответа: `INSUFFICIENT_CONTEXT`, `UNSUPPORTED_QUERY`, `CLARIFY_PERIOD`, `CLARIFY_METRIC`. К ним нельзя дописать произвольное объяснение или SELECT; они не передаются исполнителю БД.

Все GBNF-файлы включены в wheel. Изменение языка требует положительных и отрицательных примеров для грамматики и [AST-проверки](../validation.py); допустимость формы не доказывает правильность бизнес-метрики.
