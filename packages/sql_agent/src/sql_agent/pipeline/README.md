# Выполнение вопроса

Этот модуль доводит вопрос до результата: получает доступные метаданные, собирает контекст, вызывает модель, проверяет и выполняет SQL. Исправление ошибки находится здесь же, поэтому предыдущий запрос и причина ошибки не теряются между независимыми обработчиками.

[agent.py](agent.py) содержит один явный асинхронный цикл. Отдельный графовый фреймворк для этой последовательности не нужен. Каждая итерация ограничена [политикой исправлений](correction.py), а весь вопрос — общим дедлайном. Отмена проверяется между этапами и перед обращением к исполнителю.

Продолжение диалога поступает как выбранный успешный расчёт в `AgentRequest.conversation`. Его SQL проходит проверку по текущему каталогу. Этот контекст не смешивается с ошибочным SQL текущей попытки. Уточнения `CLARIFY_PERIOD` и `CLARIFY_METRIC` завершают выполнение без обращения к БД.

Поиск учитывает вопрос, выбранные условия и основание продолжения. Явно выбранный показатель определяется через `filters.metric_key`: его таблицы закрепляются в контексте вместе с таблицами предыдущего расчёта. Недоступное основание отклоняется до обращения к поисковым моделям; нехватка места для обязательных таблиц возвращается как ошибка размера контекста.

Поток связан с [поиском](../retrieval/README.md), [генерацией](../generation/README.md) и [проверкой SQL](../sql/README.md). Хранение заданий, повтор после перезапуска worker и повторная проверка права на результат выполняются бэкендом, а не этим циклом.
