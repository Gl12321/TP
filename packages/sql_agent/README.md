# SQL-агент

SQL-агент позволяет спросить о данных обычными словами и получить готовую таблицу. Например, вопрос «Сравни выручку городов за сентябрь» превращается в запрос к PostgreSQL, а ответ содержит рассчитанные значения и сам SQL. Когда для расчёта не хватает периода, определения показателя или доступных данных, агент возвращает уточнение либо причину отказа.

Это **Python-библиотека**, которую «Разбор» вызывает в фоновом процессе. Она не запускает отдельный веб-сервис и не хранит пользователей, пароли источников или историю диалогов. Такое разделение позволяет использовать то же ядро в другом приложении и менять способ запуска независимо от логики SQL.

## Как получается таблица

Приложение передаёт вопрос, выбранные условия и каталог уже разрешённых таблиц. Поиск выбирает подходящие поля, а подбор контекста добавляет таблицы, необходимые для соединений. Определение выбранного показателя и основание продолжения диалога сохраняются в контексте обязательно.

Модель составляет один SELECT. Грамматика ограничивает язык и доступные имена во время генерации; следующая проверка разбирает структуру SQL и связывает поля с источниками. Перед выполнением агент повторно получает каталог: изменение структуры или доступа прекращает текущий расчёт.

Запрос выполняет предоставленный приложением исполнитель чтения. Он возвращает настоящие строки БД. При исправимой ошибке агент передаёт модели SQL и причину ошибки, сохраняя исходный вопрос. Число исправлений и общее время ограничены. Результат не отправляется второй модели для сочинения ответа.

## Подключение

Базовой библиотеке нужны Python 3.11+ и sqlglot. Из корня репозитория:

```text
python -m pip install -e ./packages/sql_agent
```

Приложение реализует три обязательных порта и передаёт их агенту. Это структурные Python-протоколы: достаточно нужных методов, наследование не требуется.

```python
from sql_agent import AgentRequest, AgentSettings, QueryContext, SQLAgent


async def answer(question, allowed_catalog, generator, read_only_executor):
    agent = SQLAgent(
        allowed_catalog,
        generator,
        read_only_executor,
        settings=AgentSettings(max_corrections=3, timeout_seconds=600),
    )
    return await agent.run(AgentRequest(question), QueryContext())
```

Без переданного `retriever` библиотека использует поиск по словам в описании таблиц. Семантический поиск и ранжирование подключаются явно. В «Разборе» эти зависимости собирает [assistant/engine.py](../../backend/app/assistant/engine.py), а запуском заданий владеет [worker.py](../../backend/app/worker.py).

## Что получает приложение

| `AgentResult.status` | Значение |
| --- | --- |
| `success` | Таблица в `result`, SQL, число попыток, версия каталога и выбранные таблицы. Ноль строк — тоже успешный результат |
| `clarification` | Вопрос в `clarification` и код причины; SQL не выполнялся |
| `not_found` | Не найден подходящий контекст либо операция не поддерживается; это отличается от успешного SELECT, вернувшего ноль строк |
| `cancelled` | Обработка остановлена сигналом `QueryContext.cancelled` |
| `error` | Код ошибки, понятное сообщение и последний SQL, если он уже появился |

`QueryResult` содержит `columns`, `rows`, `column_types`, `sql` и `truncated`. Признак `truncated` означает, что исполнитель ограничил выдачу; такую таблицу нельзя представлять как полный набор строк. События `QueryContext.on_event` позволяют показывать текущий этап без разбора текстовых сообщений.

## Границы ответственности

Библиотека поддерживает базовую аналитику: JOIN, фильтрацию, группировки, агрегаты, CASE, даты, сортировку и LIMIT/OFFSET. Точный язык описан в [документации грамматики](src/sql_agent/sql/grammar/README.md). CTE, подзапросы, оконные функции, UNION и соединение таблицы с самой собой не поддерживаются.

Каталог и исполнитель обязаны проверять права при каждом обращении. Ограничение строк по организации и точкам, отдельная роль PostgreSQL для чтения, транзакция `READ ONLY`, таймауты и лимит результата реализуются приложением. Фильтры вопроса и инструкции модели не являются механизмом авторизации.

Грамматика и AST защищают форму запроса и границы известного каталога. Они не доказывают правильность финансовой формулы, кратности JOIN или смысла показателя. Эти свойства проверяются на контрольных вопросах с ожидаемыми результатами.
