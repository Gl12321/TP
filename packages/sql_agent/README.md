# SQL-агент

Пользователь спрашивает о данных обычными словами и получает таблицу: например, выручку по городам за месяц. Этот пакет превращает вопрос в проверенный запрос к PostgreSQL, выполняет его через переданный приложением интерфейс чтения и возвращает результат вместе с SQL. Если смысл показателя или период неоднозначны, вместо выдуманного расчёта возвращается просьба уточнить вопрос.

Пакет отделён от SaaS, чтобы одну и ту же логику можно было проверять на контрольных данных, вызывать из фонового задания и развивать без зависимости от HTTP, сессий и пользовательского интерфейса. Пользователями, правами, подключениями и сохранением результатов владеет [бэкенд](../../backend/README.md).

## Как получается ответ

1. Приложение передаёт вопрос и каталог уже разрешённых таблиц. Для продолжения диалога отдельно прикладывает выбранный успешный расчёт, а для бизнес-показателей — согласованные определения.
2. Поиск выбирает наиболее подходящие таблицы. Ранжирование учитывает их описания и поля; связующие таблицы добавляются целиком вместе с необходимым путём соединения.
3. Контекст подбирается под фактический токенизатор модели. Предыдущий расчёт и необходимые связи не отбрасываются ради формального попадания в лимит.
4. Модель генерирует один SELECT, код отказа или запрос уточнения. Грамматика ограничивает SQL разрешёнными именами и аналитическими конструкциями.
5. Проверка AST привязывает поля к источникам, раскрывает `*` только в доступные колонки и отсекает неподдерживаемые операции. Перед выполнением пакет повторно проверяет, что каталог не изменился.
6. Исполнитель приложения выполняет SELECT. Исправимая ошибка возвращается в тот же цикл; число попыток и общее время ограничены. Повторение неудачного SQL прекращает исправления.

Нейросеть не получает строки результата для написания объяснения. Возвращаемая таблица — результат исполнения запроса; комментарии людей, уведомления и штатные дашборды к этому циклу не относятся.

## Границы и подключение

[contracts.py](src/sql_agent/contracts.py) содержит простые структуры данных. [ports.py](src/sql_agent/ports.py) задаёт три внешних интерфейса: разрешённый каталог, генератор SQL и исполнитель чтения. Поиск и reranker — заменяемые внутренние компоненты. Импорт пакета не загружает PyTorch, llama.cpp или модели.

```python
from sql_agent import AgentRequest, AgentSettings, QueryContext, SQLAgent

agent = SQLAgent(
    allowed_catalog,
    generator,
    read_only_executor,
    settings=AgentSettings(max_corrections=3, timeout_seconds=600),
    retriever=retriever,
    reranker=reranker,
)
result = await agent.run(AgentRequest(question), QueryContext())
```

Каталог возвращает `CatalogSnapshot(namespace, version, tables)`. `namespace` обязан различать клиента, источник и разрешённый профиль данных; версия меняется при изменении структуры или доступа. Исполнитель возвращает `QueryResult` либо `QueryError` с признаком возможности исправления. Обработчик событий синхронный; приложение сохраняет их в своей очереди. В `QueryContext` передаётся общий сигнал отмены.

Условия первого вопроса — выбранные даты, показатель и точки — передаются отдельным словарём `AgentRequest.filters`, а не приписываются к пользовательскому тексту. В продолжении диалога текущие условия имеют приоритет над фильтрами предыдущего расчёта. Они уточняют вопрос и не заменяют обязательное ограничение доступа в исполнителе.

Если пользователь выбрал конкретный показатель, приложение передаёт его ключ в `filters.metric_key` вместе с соответствующим `MetricDefinition`. Таблицы этого определения обязательно входят в контекст, даже если короткий вопрос вроде «сравни» не нашёл их через поиск. Без явного выбора доступные определения помогают модели понять терминологию, но не заставляют включать в вопрос весь каталог.

**Проверка SQL не заменяет права PostgreSQL.** Исполнитель обязан заново проверять доступ, ограничивать строки и поля, использовать отдельную роль чтения и транзакцию `READ ONLY`, задавать таймауты и лимиты результата. Пакет не получает пароль источника и не может расширять область доступа. Приложение повторно проверяет права при публикации и чтении сохранённого результата.

Если `retriever` не передан, применяется простой поиск по словам в метаданных. Это режим небольших тестовых каталогов, а не скрытая имитация семантического поиска. Рабочий процесс использует [локальные адаптеры](src/sql_agent/adapters/README.md).

## Установка и проверка

Требуется Python 3.11 или новее. Базовая установка: `python -m pip install ./packages/sql_agent`. Для CPU сначала устанавливается PyTorch: `python -m pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cpu`, затем локальные адаптеры: `python -m pip install "./packages/sql_agent[local]"`. Общий запуск приложения выполняет подготовку зависимостей сам. Каталог моделей, скачивание и выбор профиля принадлежат общему запуску; пакет сам не читает `.env` или YAML и не скачивает веса.

После установки проверки запускаются из корня репозитория: `python -m unittest discover -s packages/sql_agent/tests`. Ресурсы GBNF входят в wheel, поэтому установленный пакет работает вне исходного репозитория.

Грамматика гарантирует ограниченную форму ответа, а не правильность финансовой трактовки. Для приёмки модели нужны русские контрольные вопросы с ожидаемыми таблицами, особенно для возвратов, календарных периодов и соединений «один ко многим». Реальное качество и RAM конкретного GGUF проверяются совместно с приложением.
