# Доступ к приложению

API соединяет интерфейс с обработкой данных. Оно принимает файл SQLite или вопрос, сообщает о ходе работы и возвращает готовую таблицу. Благодаря этой границе интерфейс может отображать результат, не загружая модель и не подключаясь к PostgreSQL самостоятельно.

## Жизненный цикл и запросы

[app.py](app.py) создаёт приложение и управляет его запуском и остановкой. [dependencies.py](dependencies.py) собирает один комплект моделей, подключений и сервисов; [main.py](main.py) предоставляет точку входа HTTP-сервера. Обработчики в [routes](routes/README.md) используют готовые компоненты.

В каждый момент разрешена одна тяжёлая операция: вопрос, импорт, переиндексация или удаление схем. Это ограничивает одновременное потребление ресурсов и не позволяет читать данные посреди их замены. Занятый сервер отвечает `busy`, не накапливая неограниченную очередь. Для этого режима используется один процесс API; общий запуск настроен в [корневом руководстве](../../README_RU.md).

Это особенно существенно для локального приложения: отдельный процесс API создал бы свой экземпляр большой модели и своё состояние блокировок. Поэтому количество процессов не является пользовательским способом ускорить запросы. Наоборот, один владелец моделей и операций делает расход памяти и порядок изменений предсказуемыми.

| Маршрут | Действие |
| --- | --- |
| POST `/question/stream` | Принять вопрос и передавать его прогресс и результат |
| POST `/queries/{request_id}/cancel` | Отменить активный вопрос |
| POST `/load_schema` | Импортировать SQLite-файлы из multipart-поля `files` |
| GET `/schema_show` | Показать доступные схемы и схемы с неактуальным индексом |
| POST `/schemas/reindex` | Перестроить поисковый индекс |
| DELETE `/drop_all_schemas` | Удалить все пользовательские схемы, кроме `public` |

Удаление затрагивает также схемы, созданные вне приложения. Системные `information_schema` и схемы с префиксом `pg_` сохраняются. При загрузке нескольких файлов атомарность действует на каждый файл отдельно; ошибка перечисляет схемы, которые уже успели загрузиться.

## Что получает клиент

Ответ на вопрос идёт потоком NDJSON: каждый JSON-объект занимает отдельную строку. Событие `accepted` подтверждает принятие вопроса, `stage` сообщает об этапе, `heartbeat` поддерживает связь, а `result` или `error` завершает поток. Все события имеют общий `request_id`.

Результат содержит `status`, `sql`, `columns`, `rows`, `truncated`, `attempts`, `error` и `error_code`. Пустая выборка отличается от ошибки; `truncated` означает, что сработало ограничение объёма выдачи. Decimal передаётся строкой без потери точности, даты — в ISO 8601. При отказе генератора статус равен `not_found`, SQL отсутствует, а код `insufficient_context` или `unsupported_query` объясняет причину.

Прогресс хранится в ограниченной очереди: старые промежуточные сообщения могут пропускаться, конечный ответ сохраняется отдельно. Разрыв связи инициирует отмену. Ресурсы остаются занятыми до завершения очистки; нативная генерация может закончить текущий вычислительный блок позже получения сигнала отмены.

## Пример взаимодействия

Интерфейс сначала получает список схем, затем отправляет вопрос и выбранные схемы. После подтверждения он может показать поиск таблиц, генерацию и выполнение как отдельные этапы. Когда приходит `result`, интерфейс строит таблицу по `columns` и `rows`; ему не требуется разбирать SQL, чтобы восстановить ответ.

Если ошибка возникла до открытия потока, она возвращается обычным HTTP-ответом. Если работа уже началась, её завершение передаётся терминальным событием потока. Клиент поэтому должен учитывать оба случая, а не считать любой HTTP 200 доказательством успешного расчёта.

Отдельный маршрут отмены нужен потому, что основное соединение уже занято чтением ответа. Отмена передаётся тому же контексту запроса, который проверяют агент, модель и исполнитель. Технические логи при этом не используются как источник пользовательского прогресса: сообщения разных задач не смешиваются в одном ответе.

## Доступ и связи

Все маршруты данных требуют `Authorization: Bearer <API_TOKEN>`. Токен должен содержать не менее 24 печатных ASCII-символов без пробелов. [Настройки](../core/README.md) также задают отдельную роль чтения БД; административное подключение не используется вместо неё.

Вопрос обрабатывает [агент](../agent/README.md). Операции со схемами согласуют [импорт](../database/migration/README.md) и [индекс](../rag/indexing/README.md). Формат ответа использует [общие типы](../domain/README.md), а клиентская реализация находится в [frontend/client.py](../../frontend/client.py).
