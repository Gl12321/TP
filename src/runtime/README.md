# Подготовка приложения

Этот модуль делает первый запуск таким же действием, как последующие: проверяет наличие моделей и готовит роль чтения в PostgreSQL. Пользователю не нужно отдельно скачивать веса и вручную создавать учётные записи БД.

## Как это работает

[run.py](../../run.py) на компьютере пользователя управляет Docker Compose. Он проверяет конфигурацию до остановки работающего приложения, поднимает БД и запускает [prepare.py](prepare.py) в отдельном контейнере. После успешной подготовки запускает API и интерфейс, дожидаясь их готовности.

[models.py](models.py) получает выбранный профиль из [config.yaml](../../config.yaml). Для GGUF проверяются размер и SHA-256. Для моделей поиска проверяется контрольная сумма каждого файла указанной версии; подходящие локальные файлы используются без повторной загрузки. Маркер готовности записывается только после проверки всего набора; изменение или исчезновение файла требует повторной проверки. Загрузками и продолжением прерванной передачи управляет Hugging Face Hub.

Роль чтения получает `pg_read_all_data` без административных полномочий. Это позволяет читать и будущие импортированные таблицы, сохраняя отдельную учётную запись для изменения данных. После старта [слой БД](../database/README.md) независимо проверяет права этой роли.

## Связь с приложением

Подготовка завершает работу до загрузки модели в [API](../api/README.md). Сам API использует локальные файлы и не скачивает модели при обработке вопроса. [core/presets.py](../core/presets.py) одинаково трактует каталог моделей для подготовки и для приложения.

Команды пользователя и требования к Docker описаны в [корневом руководстве](../../README_RU.md). Проверки подготовки без сети и Docker находятся в [test_startup.py](../../tests/test_startup.py).
