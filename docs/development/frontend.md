# Разработка frontend

Frontend превращает данные и действия backend в понятный рабочий процесс: увидеть отклонение, задать вопрос, проверить таблицу, передать наблюдение коллеге и вернуться к результату. При изменении интерфейса нужно сохранять связь между числом, условиями расчёта и доступной пользователю областью. Пустая карточка, загрузка и ошибка должны объяснять, что происходит и что можно сделать дальше.

Этот документ описывает устройство клиентского приложения и путь от небольшого исправления до сборки. Пользовательские сценарии находятся в [описании продукта](../PRODUCT.md), общая схема компонентов — в [архитектуре](../ARCHITECTURE.md), серверная сторона — в [руководстве backend](backend.md).

## Среда и запуск

Используются React 19, TypeScript, React Router 7, TanStack Query 5, TanStack Table 8, Radix Dialog и Vite 7. Точные разрешённые зависимости перечислены в [package.json](../../frontend/package.json), установленные версии закреплены [package-lock.json](../../frontend/package-lock.json). Базовая среда проекта — Node.js 24. Для редактирования интерфейса Python-библиотеки модели и сама модель не нужны; для проверки действий пользователя нужен доступный backend.

Команды ниже выполняются из `frontend` в Windows или Linux:

| Задача | Команда | Результат |
| --- | --- | --- |
| Установить зависимости по lock-файлу | `npm ci` | Локальный `node_modules`; повторять после изменения зависимостей или чистого checkout |
| Работать с горячим обновлением | `npm run dev` | Vite на `127.0.0.1:5173` |
| Проверить типы | `npm run typecheck` | Проверка исходников и тестов без публикации сборки |
| Проверить компоненты и функции | `npm test` | Однократный Vitest в jsdom |
| Работать с тестом непрерывно | `npm run test:watch` | Vitest в режиме наблюдения |
| Собрать приложение | `npm run build` | Проверка TypeScript и статические файлы `dist` |
| Проверить форматирование | `npm run format:check` | Проверка Prettier |
| Отформатировать | `npm run format` | Изменение исходников и конфигурации по правилам Prettier |

[vite.config.ts](../../frontend/vite.config.ts) направляет запросы `/api` с Vite на `http://127.0.0.1:8000`. Клиент использует относительные адреса: в коде нет отдельного адреса API из `VITE_*`. Если backend работает на другом порту, измените proxy. При занятом порте Vite может выбрать следующий; фактический адрес напечатан в терминале.

Для обычной работы открывайте адрес Vite. Для проверки готовой сборки запускайте backend, обслуживающий `frontend/dist`, либо общий контейнерный запуск. У `npm run preview` нет настроенного API proxy: он подходит для просмотра артефакта сборки, но сам по себе не даёт рабочий вход и данные. Схема production и HTTPS описаны в [документации Docker](../operations/docker.md).

## Разделение кода

Точка входа [main.tsx](../../frontend/src/main.tsx) создаёт QueryClient и подключает маршрутизатор, уведомления и сессию. Всё приложение делится на три слоя:

| Слой | Содержимое | Когда менять |
| --- | --- | --- |
| [app](../../frontend/src/app/README.md) | Маршруты, вход, принятие приглашения, сессия, workspace-контекст, оболочка | Новый раздел, общая навигация, поведение входа или переключения пространства |
| [features](../../frontend/src/features/README.md) | Предметные страницы и их собственные компоненты | Новый пользовательский сценарий или изменение существующего |
| [shared](../../frontend/src/shared/README.md) | Контракты API, запросы, элементы UI, результат, форматирование и стили | Поведение, одинаковое в нескольких сценариях |

В функциональном разделе `pages` связывает URL, запросы и компоненты. `components` содержит формы и карточки, `hooks` — отдельную логику запроса или наблюдения, `model` — функции преобразования и подписи. Не нужно создавать пустые слои заранее или добавлять файлы, которые только переэкспортируют соседний компонент. Маленькая форма, используемая одной страницей, может оставаться рядом с этой страницей, как в планах.

Общую таблицу, диалог, форматирование суммы или CSV не копируют в новую функцию продукта. При переносе предметной функции в `shared` убедитесь, что она действительно нужна нескольким разделам и не принимает решения за backend.

## Маршруты и ссылки

[App.tsx](../../frontend/src/app/App.tsx) лениво загружает страницы и проверяет серверные capabilities перед их показом. Маршруты пространства начинаются с `/w/:workspaceId`.

| Адрес внутри пространства | Назначение | Важные параметры |
| --- | --- | --- |
| `overview` | Факт, план, сравнение периодов и городов | `month`, `stores`, `metric` |
| `stores`, `stores/:storeId` | Список точек и карточка точки | Общий период и показатель; точка карточки фиксирована маршрутом |
| `assistant/:conversationId?` | Личные вопросы и результаты | `q` для истории; общая область следующего вопроса |
| `reports/:reportId?` | Сохранённые результаты и повторные расчёты | `q` для списка, `run` для выбранной попытки |
| `cases/:caseId?` | Разборы, вопросы сотрудникам и измерения | `q`, `filter` |
| `data` | Подключения, обращения, показатели, планы | `tab=sources\|issues\|metrics\|plans`; `issue`, `issue_q`, `issue_status` |
| `settings` | Профиль, команда, точки | `tab=profile\|members\|stores` |

`/invite` обрабатывает приглашение. Секрет приглашения находится во фрагменте URL, чтобы не отправляться серверу при обычном открытии страницы. `/` выбирает первое доступное пространство и его начальную страницу: аналитик попадает в отчёты, управляющий единственной точки — в её карточку, технический администратор — в настройки, остальные пользователи аналитики — в обзор. Это задаёт [workspaceStart](../../frontend/src/app/workspace.tsx).

Общие фильтры хранятся в URL через `useFilters`. При отсутствии периода выбирается предыдущий месяц. Оболочка переносит `month`, `stores` и `metric` между основными разделами; поисковые параметры списка остаются ответственностью самого списка. Обновляйте `URLSearchParams` поверх существующего значения, чтобы изменение вкладки не стирало область расчёта.

У страниц нет собственного права расширять область по адресной строке. Наличие `storeId`, `reportId` или `run` в ссылке — запрос показать объект, а не доказательство доступа к нему.

## Сессия, права и приватное состояние

[SessionProvider](../../frontend/src/app/session.tsx) получает `/auth/session`. Backend возвращает пользователя, пространства, роли, области точек, capabilities и CSRF-токен. Cookie сессии HttpOnly: JavaScript его не читает. CSRF хранится только в памяти модуля API-клиента и добавляется к изменяющим запросам.

`useWorkspace().can(capability)` управляет доступностью UI. Проверяйте конкретное действие, например `reports:write`, а не текстовое название роли. Роль описывает рабочую задачу, но реальные права и область возвращает сервер. В частности, `sources:manage` не означает право читать финансовые данные источника. Для выбора источника ассистента учитываются его готовность, доступные таблицы и аудитория `reader_ids`, а не только наличие в административном списке.

При выходе, смене аккаунта или истечении сессии запросы отменяются, приватный кэш удаляется. При переключении пространства очищается кэш предыдущего пространства. Изменение набора прав обновляет данные workspace; отказ 403 инициирует повторное чтение сессии. Нельзя сохранять старый закрытый результат под сообщением об ошибке доступа.

Черновики [useDraft](../../frontend/src/shared/ui/useDraft.ts) используют тот же workspace-кэш. Имя должно включать назначение формы и идентификатор записи или разговора. Они переживают переходы между страницами пространства, но не перезагрузку браузера, выход или переключение пространства. Данные пользователя, SQL, пароли и токены не нужно добавлять в `localStorage` или `sessionStorage`.

## Контракт с backend и кэш

[client.ts](../../frontend/src/shared/api/client.ts) — единая точка HTTP-запросов. Он добавляет префикс `/api/v1`, cookie, CSRF и нормализует ошибки в `ApiError(status, code, message)`. Для ресурсов пространства используйте `workspacePath`; параметры кодируйте через `queryString`. Передавайте `AbortSignal` из TanStack Query в `get` или `getPage`, чтобы запросы закрытого экрана можно было отменить.

[contracts.ts](../../frontend/src/shared/api/contracts.ts) описывает формы ответов. Это TypeScript-типы, а не проверка произвольного JSON во время выполнения. Изменение поля API требует согласованного изменения серверной схемы, этого контракта и использующих его компонентов. Нельзя исправлять несовпадение ответа необоснованным `as` или `any`. Форматы API описаны в [backend/API.md](../../backend/API.md).

Ключ ресурса строится через `keys.resource(workspaceId, name, ...parameters)` из [queries.ts](../../frontend/src/shared/api/queries.ts). В параметры ключа входят все условия, влияющие на ответ: идентификатор записи, период, показатель, поиск, фильтр и область. После mutation обновляйте изменённый объект и инвалидируйте зависимые списки/расчёты. Общий сброс workspace оправдан для изменения доступа или параметров, влияющих на многие расчёты; обычный комментарий не требует сбрасывать всё приложение.

Глобально запросы считаются свежими 20 секунд и обновляются при возвращении в окно. Для 401/403/404 повтор отключён, прочая ошибка допускает один повтор. Mutation автоматически не повторяется. У сессии и наблюдаемых ресурсов есть собственные настройки. Это не механизм офлайн-работы: сервер остаётся источником состояния.

## Списки, поиск и пагинация

История разговоров, отчёты, разборы, связанные разборы точки и обращения используют серверный поиск и `useInfiniteQuery`. [getPage](../../frontend/src/shared/api/client.ts) читает массив ответа и `X-Next-Cursor`; следующий запрос передаёт курсор API. Для поиска используется [useDebouncedValue](../../frontend/src/shared/ui/useDebouncedValue.ts): URL и поле меняются сразу, сетевой запрос — после паузы 250 мс.

Счётчик списка показывает количество уже полученных элементов. Это не общее число в базе. Продолжение выдачи определяется курсором: пустая страница при наличии курсора не означает конец, поскольку более ранние записи могут пройти проверку доступа. Ошибка следующей страницы сохраняет уже загруженный список и показывает повтор рядом с кнопкой дозагрузки. Ошибку первого запроса показывают состоянием страницы.

Сортировка и постраничный просмотр внутри готовой SQL-таблицы работают с уже возвращёнными строками. Они не выполняют новые SQL-запросы. Поэтому сортировку ограниченного результата нельзя представлять как рейтинг по всей базе.

## Формы и повторная отправка

Используйте [Form, Field, Button, Modal](../../frontend/src/shared/ui/Common.tsx) и `InlineError`. `Field` должен содержать непосредственно одно поле `input`, `select` или `textarea`: он связывает подпись через `htmlFor`/`id`, подсказку — через `aria-describedby`. Собственный идентификатор и дополнительные описания сохраняются.

Во время отправки блокируйте редактируемые поля, повторную отправку и закрытие изменяющего диалога. Ошибку оставляйте рядом с формой; успешное действие подтверждайте, сбрасывайте черновик после подтверждения сервера и обновляйте соответствующий кэш. Проверка браузера помогает пользователю исправить ввод, но не заменяет серверную валидацию.

Создание отчёта, разбора и технического обращения использует [useSubmissionKey](../../frontend/src/shared/ui/useSubmissionKey.ts). Он выдаёт один `idempotency_key` для неизменённого тела и новый для изменённого. После успеха вызывается `clearKey()`. Повтор после потери ответа должен отправить прежний ключ; создание UUID при каждой попытке разрушит защиту от дублей. Запросы ассистента и повторные расчёты отчёта имеют свои ключи операций в соответствующих страницах. Отключение кнопки и идемпотентность решают разные задачи и используются вместе.

## Ассистент и результат

[AssistantPage](../../frontend/src/features/assistant/pages/AssistantPage.tsx) управляет выбором источника, областью следующего вопроса, разговором и основанием продолжения. Исходный `Run` содержит свой контекст. Нельзя подменять его период текущими фильтрами страницы или автоматически присоединять всю историю к опубликованному отчёту.

[useRun](../../frontend/src/features/assistant/hooks/useRun.ts) подключает `EventSource` к `/runs/:id/events`. События с возрастающим номером инициируют обновление run и разговора; одновременно активный run опрашивается раз в 2,5 секунды. Потеря SSE показывает восстановление соединения и сохраняет опрос. Завершение прекращает наблюдение, закрытие вкладки освобождает клиентское соединение. Серверная работа отменяется только запросом `/runs/:id/cancel`.

[RunCard](../../frontend/src/features/assistant/components/RunCard.tsx) различает очередь, выполнение, запрос остановки, остановку, уточнение, ошибку и успех. SQL неуспешной попытки обозначается именно как последняя попытка, без подтверждённой таблицы. Ошибка чтения run скрывает устаревший результат и предлагает повторить запрос.

Для готовой таблицы используется [ResultPanel](../../frontend/src/shared/results/ResultPanel.tsx): вопрос, время, источник, точки, период, таблица или график, SQL, параметры фактического выполнения, CSV и действия сохранения. Сгенерированный SQL и SQL после серверного применения области показываются отдельно. Кнопки сохранения проверяют `reports:write` и `cases:write`.

Нельзя незаметно заменять результат отчёта при обновлении. [ReportsPage](../../frontend/src/features/reports/pages/ReportsPage.tsx) показывает исходный снимок и историю повторов; параметр `run` выбирает конкретную попытку. Новый запуск выполняет сохранённый SQL без нового обращения к модели.

## Деньги, графики и экспорт

[format.ts](../../frontend/src/shared/ui/format.ts) форматирует и сравнивает десятичные строки без преобразования в двоичный `Number`. Передавайте ему исходную строку API. `null` означает отсутствие значения; ноль остаётся нулём. Отображаемое округление карточки не должно менять исходную сумму или использоваться в последующем расчёте.

[ResultChart](../../frontend/src/shared/results/ResultChart.tsx) визуализирует выбранные столбцы в исходном порядке. Он не агрегирует повторяющиеся подписи, не превращает пропуски в нули и явно ограничивает отображение первыми 20, 50 или 100 строками. SVG-координаты используют точность `Number`; точные значения остаются в таблице и подписях. Полнота графика не может быть выше полноты исходной выдачи.

[export.ts](../../frontend/src/shared/results/export.ts) создаёт CSV из исходных значений, экранирует разделители/кавычки и защищает текстовые ячейки от выполнения формул табличным редактором. Для `truncated` интерфейс говорит «Скачать показанные строки», а имя файла содержит `partial`. Не добавляйте в CSV выдуманные итоги или строки, отсутствующие в сохранённом результате.

Штатные показатели обзора, сравнение периодов, планы и повторные измерения рассчитывает backend по определениям. Browser отображает ответ и основание расчёта. Добавление новой карточки не должно порождать второй алгоритм бизнес-метрики в JavaScript.

## Визуальная система и доступность

Основная палитра и токены находятся в [global.css](../../frontend/src/shared/styles/global.css). Оттуда подключаются `components.css` для общих элементов, `layout.css` для оболочки и входа, `features.css` для предметных страниц, `charts.css` для графиков. Первоначальная настройка имеет собственный [setup.css](../../frontend/src/features/onboarding/styles/setup.css). Шрифты берутся из локального системного стека, внешняя загрузка не требуется.

Стиль использует светлую рабочую поверхность, тёмную навигацию, насыщенный синий для действия и отдельные цвета состояния. Цвет дополняет подпись, а не заменяет её. Используйте существующие CSS-переменные и элементы; новые размеры и состояния должны соответствовать соседним разделам.

Оболочка [useMobileNavigation](../../frontend/src/app/shell/hooks/useMobileNavigation.ts) закрывает меню по Escape, удерживает фокус в открытой панели и исключает скрытую панель из взаимодействия. Radix Dialog обеспечивает поведение модальных окон. У кнопок с одной иконкой должна быть доступная подпись; у таблицы — caption; у нового поля — видимая подпись. Не удаляйте видимый фокус, не заменяйте кнопки кликабельными `div` и учитывайте `prefers-reduced-motion`.

При изменении страницы проверяйте широкое окно, ширину телефона, длинное название, много строк, пустую выдачу и ошибку. Таблица может прокручиваться внутри контейнера; вся страница не должна разъезжаться по горизонтали. Ошибка дозагрузки не должна уничтожать ранее доступный список, а ошибка доступа — оставлять закрытую финансовую таблицу на экране.

## Как внести изменение

### Исправить текст или внешний вид

Найдите компонент в соответствующем `features`, а общий элемент — в `shared`. Измените текст/разметку рядом со сценарием; общий стиль меняйте в общем CSS только если это действительно правило для всех использований. Для локальной правки достаточно проверки типов и просмотра затронутых состояний. После изменения поведения выполните относящийся к нему тест.

### Добавить действие с API

Сначала согласуйте серверную операцию и формат ответа. Обновите `contracts.ts`, добавьте вызов через общий клиент, проверьте capability, состояния отправки и ошибки. После подтверждения обновите объект или инвалидируйте правильный ключ. Для создаваемого объекта, который нельзя продублировать повтором, используйте серверный контракт идемпотентности и стабильный ключ формы. Сохраните черновик при ошибке, сбросьте после успеха.

### Добавить страницу

1. Определите, какую пользовательскую задачу закрывает страница и какой существующий раздел ей соответствует.
2. Поместите страницу в `features/<раздел>/pages`; вынесите формы, карточки или самостоятельный запрос, когда у них есть отдельная ответственность.
3. Добавьте ленивый маршрут и capability в `App.tsx`, пункт навигации при необходимости — в `app/shell/model/navigation.ts`.
4. Получайте workspace из контекста; условия, которые должны пережить обновление страницы и открытие ссылки, храните в URL.
5. Добавьте запросы с полным ключом кэша, обработайте загрузку, отсутствие данных, ошибку, повтор и потерю доступа.
6. Проверьте переходы из соседних сценариев, клавиатуру и мобильную ширину. Дополните README раздела назначением и связями.

### Изменить контракт или роль

Меняйте backend и клиент согласованно. Тестируйте пользователя с нужным действием, пользователя без действия и пользователя с тем же действием, но другой областью точек/источников. Проверяйте прямую ссылку на объект, а не только отсутствие пункта меню. В [roles.ts](../../frontend/src/features/settings/model/roles.ts) меняется объяснение роли; реальные capabilities задаёт backend.

## Проверка и публикация

Проверки типов включают `strict`, неиспользуемые переменные и параметры. Компактный набор [tests](../../frontend/tests/README.md) проверяет десятичную точность, CSV, cookie и CSRF, показ SQL, удаление закрытого результата и ключи повторной отправки. Графики, все формы, мобильная навигация и полный цикл приглашений не покрыты отдельными автоматическими сценариями; при изменении их поведения нужен предметный просмотр.

Один браузерный сценарий проходит вход, создание точки и разбора, комментарий и выход через настоящий API. `APP_UI_CREDENTIALS` указывает на приватный JSON с `url`, `email`, `password` существующего руководителя-владельца отдельной тестовой установки. Сценарий оставляет созданные записи; демонстрационные аккаунты и данные для него не используются. Источник финансовых данных и модель ему не нужны. Команды Playwright и формат файла — в [frontend/tests](../../frontend/tests/README.md). Пропуск сценария не считается успешной проверкой.

Для ручного знакомства с продуктом и сравнения ролей есть отдельные [демонстрационные сценарии](../demo/README.md). Их постоянное состояние не является фикстурой Vitest или Playwright.

Перед выпуском изменения с поведением выполните связанные тесты и `npm run build`; при изменении общих контрактов и компонентов выполните весь `npm test`. Сам по себе успешный build подтверждает типы и сборку, а не доступность базы и worker.

`dist`, `node_modules` и результаты проверок — воспроизводимые локальные артефакты. В репозитории остаются исходники, `package.json`, lock-файл и конфигурация. В Docker frontend собирается на этапе Node и попадает в образ приложения; в финальной среде его обслуживает Python API. Версии frontend и backend выпускаются вместе, чтобы типы и ответы не расходились. Общий порядок запуска, обновления и развёртывания — в [руководстве эксплуатации](../operations/README.md).
