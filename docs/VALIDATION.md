# Что проверено

Состояние на 30 сентября 2026 года. Проверки подтверждают работу отдельных частей приложения и их контрактов: от выбора модели при запуске до показа таблицы и выполненного SQL. Полный запуск с настоящими весами и PostgreSQL ещё не выполнен.

Использован Python 3.12.10 на Windows. Зависимости для проверок установлены в служебные каталоги `.tools/test-packages` и `.tools/ui-packages`, отдельно от системного Python. Модели не скачивались, внешние сервисы не запускались. Docker в текущем окружении отсутствует.

Проверки используют настоящий SQLGlot, LangGraph, FastAPI, SQLAlchemy, Jinja2 и Streamlit там, где проверяется поведение этих библиотек. Генерация и поиск по моделям в тестах подменяются управляемыми зависимостями. GBNF дополнительно компилируется имеющейся локальной `llama.dll` без загрузки весов.

## Что подтверждают тесты

Подготовка запуска проверена без Docker и сети: порядок операций, проверка конфигурации до остановки приложения, сохранение секретов, блокировка одновременных запусков, выбор модели и обработка прерывания. Для файлов моделей проверены контрольные суммы, повторное использование локальных файлов, повреждённые загрузки и недействительные маркеры готовности. Проверки памяти учитывают обычную RAM и ограничения Linux cgroup.

Для SQL проверены допустимые конструкции грамматики, имена таблиц и столбцов, агрегаты, запрещённые операции и переходы к исправлению. Во время проверки обнаружено, что SQLGlot мог отбрасывать третий аргумент `DATE_TRUNC` при разборе. Теперь такой запрос отклоняется до потери информации об аргументах; регрессионный тест проходит.

Для промптов проверены полнота описания структуры, отдельные сообщения исправления, управляющие токены и шаблон диалога. Эти проверки подтверждают состав и границы контекста, но не качество SQL конкретной модели на предметных вопросах.

Streamlit AppTest запускает настоящий экран с подменённым API. Проверены таблица перед свёрнутым блоком SQL, доступность SQL при пустой выдаче, отдельное обозначение неуспешного запроса и отсутствие выдуманного запроса при отказе. Лимит формы загрузки теперь следует настройке приложения вместо стандартных 200 МиБ Streamlit. Клиент отдельно проверяется на обрыв потока, разделённые UTF-8-символы, ограничения ответа и гонку отмены с готовым результатом.

## Что остаётся проверить при полном запуске

Сборка Docker-образов и работа Compose пока не проверены исполнением. Конфигурация и порядок запуска просмотрены, а вызовы управляющего скрипта проверены с подменённым Docker. Это не заменяет сборку контейнеров на Windows и Linux.

Интеграционным тестам нужна отдельная PostgreSQL: импорт, откат, внешние зависимости, точность чисел, права чтения, таймауты и отмена должны пройти с настоящими транзакциями. Подключение задаётся по инструкции в [tests/README.md](../tests/README.md).

С локальными весами нужен полный сценарий в браузере: импорт SQLite, вопрос, таблица и SQL, исправление ошибки, отмена и переиндексация. AppTest проверяет элементы экрана, но не визуальное оформление и работу буфера обмена в браузере.

Для выбранной модели нужно измерить пиковую RAM и время ответа при совместной работе LLM, поиска, PostgreSQL и ОС. В частности, присутствие профиля Qwen3.5 27B в каталоге не подтверждает его устойчивую работу на ноутбуке с 24 ГБ RAM.
