# Документация продукта

Документация объясняет, какую задачу решает «Разбор», как связаны его части и чем подтверждено их поведение. Начать знакомство лучше с [корневого руководства](../README_RU.md): там показан путь от вопроса к таблице и совместному решению команды.

## Текущая реализация

| Документ | Когда нужен |
| --- | --- |
| [Backend](../backend/README.md) | Понять роли, источники, аналитические определения, задания и коммуникацию |
| [Frontend](../frontend/README.md) | Понять страницы, общую оболочку, состояния результата и взаимодействие с API |
| [SQL-ядро](../packages/sql_agent/README.md) | Проследить выбор таблиц, генерацию, проверку и выполнение SQL |
| [API](../backend/API.md) | Интегрировать клиент с конкретными маршрутами и контрактами |
| [Runtime](../runtime/README.md) | Разобраться в единой команде, моделях и порядке подготовки |
| [Эксплуатация](OPERATIONS.md) | Подключить БД, настроить окружение, хранить секреты и восстанавливать данные |
| [Проверки](VALIDATION.md) | Узнать, что запускалось в действительности и что ещё не подтверждено |
| [Тесты](../tests/README.md) | Повторить автономные и интеграционные сценарии |

README основных каталогов сначала объясняют назначение компонента, затем логику с необходимыми ссылками на код и только потом условия использования. Числовые настройки находятся в [YAML](../config.yaml), чтобы руководство не превращалось в копию конфигурации.

## Исследования и замысел

[Исследовательский раздел](research/README.md) сохраняет сравнение продуктовых направлений и основания выбора франчайзинговой аналитики. [Итоговая концепция](research/franchise/README.md), [архитектурный замысел](research/franchise/architecture.md) и [поведение ассистента](research/franchise/assistant.md) описывают принятый курс; некоторые подробности изменены при реализации.

[Макеты](prototypes/README.md) демонстрируют ранние взаимодействия на вымышленных данных. Они отделены от рабочего frontend и не подтверждают наличие соответствующего API. Старые ссылки на заменённый код привязаны к исторической версии репозитория, чтобы сохранить смысл исследовательских выводов.

[FEATURES.md](FEATURES.md) и [RESEARCH.md](RESEARCH.md) — материалы отбора возможностей, а не перечень уже доступных функций. При расхождении с ними текущее поведение описано в README приложения, документации API и тестах. `VALIDATION.md` фиксирует именно выполненные проверки.
