# Документация «Разбора»

«Разбор» помогает сотрудникам сети получать ответы из базы обычными словами и превращать результаты в совместную работу: сохранить расчёт, задать вопрос ответственному, зафиксировать решение и повторно измерить показатель. Здесь описано поведение текущего продукта и устройство его реализации.

## С чего начать

| Задача | Документ |
| --- | --- |
| Понять идею, роли и доступные пользовательские действия | [Продукт и функционал](PRODUCT.md) |
| Разобраться в процессах, структуре кода и данных | [Архитектура](ARCHITECTURE.md) |
| Запустить приложение и подключить первую базу | [Запуск и эксплуатация](operations/README.md) |
| Установить окружение на новой машине пошагово | [Установка с нуля: Windows и Linux](operations/install.md) |
| Изменить проект и подобрать нужные проверки | [Руководство разработчика](development/README.md) |
| Посмотреть продукт, финансовые данные и работу разных ролей | [Демонстрационные сценарии](demo/README.md) |
| Проверить изменение кода автоматически | [Автоматические проверки](development/testing.md) |

Пользовательский документ объясняет, что происходит на экране и как взаимодействуют сотрудники. Демонстрация позволяет пройти эти действия руками в отдельном окружении. Архитектура показывает, какая часть системы отвечает за поведение продукта. Руководства разработчика и оператора переходят к конкретным файлам, контрактам, командам и ограничениям. Автоматические проверки используют собственные данные и не изменяют демонстрационное пространство.

## Разработка по компонентам

| Компонент | Область ответственности | Руководство |
| --- | --- | --- |
| Backend | Пользователи, пространства, доступ, источники, показатели, планы, задания и совместная работа | [backend.md](development/backend.md), [HTTP API](../backend/API.md) |
| SQL-агент | Вопрос → подходящая структура базы → проверенный SQL → результат; самостоятельная Python-библиотека | [sql-agent.md](development/sql-agent.md) |
| Frontend | Навигация, формы, состояния запросов, таблицы, графики и действия команды | [frontend.md](development/frontend.md) |

README внутри модулей объясняют их назначение, основные файлы и связи с соседними директориями. Подробные правила общего поведения находятся в этих руководствах, поэтому изменение одной функции не требует переписывать несколько копий одной спецификации.

## Эксплуатация

- [Установка с нуля](operations/install.md): Python, WSL 2, Docker, права пользователя, перезагрузка и проверка готовности.
- [Запуск](operations/README.md): зависимости, последовательность подготовки, первый вход, подключение источника и диагностика.
- [Docker](operations/docker.md): шесть сервисов, сборки, сети, тома, готовность, HTTPS и обновления.
- [Конфигурация](operations/configuration.md): YAML, приоритеты, секреты, модели и применение настроек.
- [Резервирование](operations/backup.md): архив, восстановление в новую БД, переключение и проверка.

Настройки хранятся в [config.yaml](../config.yaml), зависимости — в соответствующих файлах требований и lock-файле frontend. Документы объясняют их смысл и порядок применения; значения по умолчанию не дублируются отдельным справочником.
