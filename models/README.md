# Модели: вопрос, поиск и SQL

Модель нужна там, где человек формулирует вопрос свободно, а база требует точного запроса. В «Разборе» одна LLM составляет SQL, а две небольшие модели помогают выбрать подходящие таблицы. Работа команды, права и готовые показатели обходятся без генерации текста.

Основная LLM выбирается при запуске. В памяти используется один профиль; можно хранить несколько скачанных файлов и переключаться между ними. [Каталог YAML](../config.yaml) закрепляет точные версии, имена, размеры и контрольные суммы. Все основные профили относятся к **Qwen3.5**.

## Три размера основной модели

| Профиль | Квантование | Размер GGUF | Назначение |
| --- | --- | ---: | --- |
| `qwen3.5-4b` | Q5_K_M | 2,93 ГиБ | Наиболее лёгкий вариант для разработки и небольших каталогов |
| `qwen3.5-9b` | Q5_K_M | 6,13 ГиБ | Вариант по умолчанию для локальной работы |
| `qwen3.5-27b` | Q3_K_M | 12,58 ГиБ | Более тяжёлая модель для сравнения качества на своих вопросах |

Это размеры файлов, **не измеренная оперативная память**. Дополнительно нужны KV-кеш и рабочие буферы движка, поиск, Python, PostgreSQL, браузер и ОС. На машине с 24 ГБ RAM 27B требует отдельного замера; нельзя обещать устойчивость по одному размеру GGUF. Текущее ограничение контекста — 4096 токенов, а генерация по умолчанию работает на CPU. Модель большего размера может отвечать существенно дольше; она также не гарантирует правильного расчёта.

GGUF нужен выбранному локальному движку `llama.cpp`. Квантование уменьшает размер весов, а шаблон диалога внутри файла определяет оформление запроса к модели. [Адаптер](../packages/sql_agent/src/sql_agent/adapters/README.md) использует этот шаблон, отключает thinking для ограниченной SQL-генерации, проверяет контекст и следит за доступной памятью. Проверка памяти снижает риск отказа, но не является резервированием RAM у операционной системы.

## Как выбираются таблицы

`intfloat/multilingual-e5-small` превращает вопрос и описания таблиц в векторы. Для E5 явно различаются префиксы вопроса и документа; используется нормализация и размерность 384. Это важно для корректного сравнения, в том числе русскоязычных вопросов.

`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` повторно оценивает найденных кандидатов. Его оценка используется для порядка таблиц; произвольный порог, как будто это вероятность правильности, не применяется. Итоговый набор дополнительно учитывает связи и бюджет контекста.

Поисковый кеш разделён по рабочему пространству, источнику, области и версии каталога. Смена embedder меняет отпечаток индекса, поэтому старые векторы не смешиваются с новыми. Подробнее — в [поиске SQL-пакета](../packages/sql_agent/src/sql_agent/retrieval/README.md).

## Подготовка и смена

```text
python run.py --list-models
python run.py --model qwen3.5-4b
python run.py --model qwen3.5-9b
python run.py --model qwen3.5-27b
```

[Подготовка](../runtime/models.py) проверяет размер, заголовок и SHA-256 GGUF. Для файлов поиска проверяются закреплённая версия и контрольные суммы каждого файла. После успешной проверки сохраняется manifest; неизменившиеся файлы можно использовать без повторного скачивания. Исполнитель получает модели только для чтения и работает в offline-режиме.

Каталог `models` исключён из Git. Наличие весов на диске не означает, что они загружены в память. Для работы без загрузки моделей существует `python run.py --without-ai`.

При добавлении профиля нужны совместимость архитектуры и шаблона с движком, проверка файлов, контрольные вопросы с ожидаемыми таблицами и измерение пикового расхода памяти. Текущее состояние таких проверок указано в [VALIDATION.md](../docs/VALIDATION.md).
