# Обсуждение с проверяемым основанием

Разбор связывает наблюдение по точке или группе точек с вопросом ответственному сотруднику. Участники добавляют проверенные обстоятельства, задают адресные вопросы и отвечают на них. Итог фиксирует автор, назначенный ответственный, руководитель или региональный менеджер. Прикреплённая таблица остаётся отдельным неизменяемым основанием. Получатель должен иметь доступ ко всей области обсуждаемого результата.

[Создание разбора](components/CaseCreateDialog.tsx) задаёт область и предмет. [Страница разборов](pages/CasesPage.tsx) выбирает список или [карточку обсуждения](components/CaseView.tsx), где показаны комментарии, адресные вопросы, ответы и итог. Список получателей приходит от API для всей области разбора; после изменения команды он загружается заново. Новое сообщение не меняет данные источника.

Комментарии и вопросы доступны участникам с `cases:write` в открытом разборе. Кнопка итога дополнительно учитывает автора, ответственного и руководящие роли, как серверная операция закрытия. После завершения обычное обсуждение недоступно; проверку доступа к карточке и её основанию выполняет API.

[Измерения](components/Measurements.tsx) показывают серверные снимки штатного показателя и позволяют автору повторить измерение за другой период, включая проверку после зафиксированного итога. Прежнее наблюдение и вывод сохраняются; новый результат не возобновляет обсуждение автоматически. Разница относится к сопоставимому составу точек, а не объявляется доказанным эффектом решения.

Представления «Мои» и «Ждут моего ответа» разделяют собственные разборы и адресные вопросы. Черновики комментария, вопроса и итога сохраняются раздельно в памяти при переходах внутри пространства. Перезагрузка страницы, выход, смена пространства или аккаунта сбрасывают их; на сервер черновики не отправляются.

Поиск и фильтр списка сохраняются в URL и выполняются сервером. Разборы загружаются страницами до 50 записей, «Показать ещё» продолжает выдачу по курсору, а счётчик показывает уже загруженное количество. Пустая страница с курсором допускает более ранние доступные записи: загрузку можно продолжить. Ошибка обновления или следующей страницы сохраняет текущий список и позволяет повторить запрос.

Разбор можно создать из [точки](../stores/README.md) либо результата [ассистента](../assistant/README.md). Личная история вопросов не передаётся коллегам. Уведомления отображает общий [AppShell](../../app/AppShell.tsx), а разрешение на чтение основания и участие независимо проверяет backend.

[Подписи состояний](model/status.ts) используются в списке, карточке обсуждения и странице точки. Повторная отправка неизменённой формы создания использует тот же ключ операции, чтобы повтор после сетевой ошибки не создавал второй разбор.
