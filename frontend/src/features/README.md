# Пользовательские сценарии

Каждый раздел здесь отвечает на конкретную задачу команды. Разделы используют один контракт данных, поэтому из показателя можно перейти к точке, из вопроса — к таблице, из таблицы — к отчёту или обсуждению без повторного ввода основания.

| Раздел                           | Задача                                                         |
| -------------------------------- | -------------------------------------------------------------- |
| [overview](overview/README.md)   | Оценить показатели и сопоставить периоды по одинаковой области |
| [stores](stores/README.md)       | Открыть точку, увидеть её контекст и связанные разборы         |
| [assistant](assistant/README.md) | Получить таблицу по вопросу и продолжить выбранный расчёт      |
| [reports](reports/README.md)     | Вернуться к сохранённому результату или повторить его SQL      |
| [cases](cases/README.md)         | Задать предметный вопрос сотруднику и зафиксировать итог       |
| [data](data/README.md)           | Подключить данные, определить показатели и планы               |
| [settings](settings/README.md)   | Назначить доступ, пригласить команду и управлять аккаунтом     |
| [onboarding](onboarding/README.md) | Довести новое пространство до первого расчёта по реальным данным |

Страницы получают идентификатор пространства из [app](../app/README.md). Серверные данные читаются через TanStack Query с ключами, включающими пространство; после изменения соответствующие запросы обновляются. Общая таблица, экспорт, формы и API-клиент находятся в [shared](../shared/README.md), а не копируются между разделами.

Внутри раздела `pages` собирает экран, `components` содержит его формы и карточки, `hooks` — повторно используемые запросы и наблюдение, `model` — подписи и проверку значений. Папки создаются только при наличии соответствующего кода. В [data](data/README.md) отдельными направлениями выделены подключения, показатели, планы и технические обращения. Импорты ведут прямо к файлам реализации.

Новый сценарий проектируется вокруг действия пользователя и его полномочий: отдельно показываются загрузка, пустой результат, ошибка и доступное продолжение. Как добавить страницу, запрос или форму без дублирования общих механизмов — в [руководстве разработчика](../../../docs/development/frontend.md).
