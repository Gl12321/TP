# Автоматические проверки интерфейса

Компактный набор защищает наиболее дорогие ошибки: потерю точности сумм, небезопасный экспорт, неверное основание результата, сохранение данных после отзыва доступа и дублирование отправок. Это выборочная проверка ключевых контрактов. Графики, все формы, мобильная навигация и полный цикл приглашений отдельными автоматическими сценариями здесь не покрываются.

## Устройство

| Файл                                           | Контракт                                                                                                                      |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| [format.test.ts](format.test.ts)               | Десятичная точность, различие нуля и отсутствия данных, защита CSV от формул                                                  |
| [client.test.ts](client.test.ts)               | Cookie, CSRF, явное пространство запроса и событие отзыва доступа                                                             |
| [results.test.tsx](results.test.tsx)           | Таблица, усечённая выдача, SQL с параметрами области доступа, очистка результата при отказе сервера, повторная отправка формы |
| [workspace.spec.ts](browser/workspace.spec.ts) | Вход, новая точка, разбор, комментарий и выход через реальный API                                                             |

Vitest работает в jsdom; [setup.ts](setup.ts) подключает проверки DOM и очистку между тестами. Playwright использует отдельно запущенное приложение с настоящим API. Демонстрация продукта живёт отдельно: она не является тестовым набором и не поставляет этим проверкам фикстуры.

## Быстрая проверка

Из корня проекта:

```text
python tools/check.py frontend
```

Команда выполняет Vitest и TypeScript. Из `frontend` доступны `npm test` и `npm run typecheck`; для одного файла — `npm test -- tests/results.test.tsx`. Общий порядок описан в [руководстве проверок](../../docs/development/testing.md).

## Проверка в браузере

Нужны запущенный изолированный экземпляр приложения, рабочая PostgreSQL, собранный интерфейс и аккаунт руководителя с правами владельца рабочего пространства. Сценарий создаёт точку, разбор и комментарий; записи остаются в тестовой установке. Подключение клиентского источника, модели и подготовленные демонстрационные данные ему не нужны.

Сохраните приватный файл `.runtime/ui-credentials.json` вне Git:

```json
{
  "url": "http://127.0.0.1:8000",
  "email": "test-director@example.test",
  "password": "пароль-тестового-аккаунта"
}
```

PowerShell, из корня:

```powershell
$env:APP_UI_CREDENTIALS = "$PWD/.runtime/ui-credentials.json"
$env:PLAYWRIGHT_CHANNEL = "msedge"
python tools/check.py browser
```

Linux, из корня:

```bash
APP_UI_CREDENTIALS="$PWD/.runtime/ui-credentials.json" python tools/check.py browser
```

`PLAYWRIGHT_CHANNEL=msedge` выбирает установленный Edge; без этой переменной нужен Chromium для Playwright. [Конфигурация](../playwright.config.ts) сама не запускает приложение и не устанавливает браузер. Прямой `npm run test:browser` без файла учётной записи пропускает сценарий: это не успешная проверка. Скриншот ошибки остаётся в игнорируемом `test-results`.
