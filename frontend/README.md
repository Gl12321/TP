# Интерфейс «Разбора»

Интерфейс помогает команде сети разобраться в данных и договориться о действиях. Руководитель сравнивает точки и выполнение плана, аналитик готовит расчёты, управляющий объясняет ситуацию на своей точке. Когда готового показателя недостаточно, пользователь пишет вопрос обычными словами и получает таблицу. Её можно проверить по SQL, сохранить как отчёт и обсудить с коллегой в разборе.

У всех ролей одно приложение с общими понятиями и ссылками на результаты. Различаются доступные действия, точки, источники и начальная страница. Личный диалог с ассистентом остаётся личным; в совместную работу передаётся выбранный результат. Полное описание продукта и ролей находится в [руководстве по функционалу](../docs/PRODUCT.md).

## Как устроено приложение

React и TypeScript формируют страницы, React Router управляет адресами, TanStack Query получает данные Python API и обновляет их после действий. TanStack Table отвечает за таблицы, Radix Dialog — за модальные окна. Vite собирает HTML, JavaScript и CSS в `dist`; в рабочем развёртывании эти файлы отдаёт backend с того же адреса, что и API. Отдельный Node.js-сервер для пользователей не требуется.

| Слой | За что отвечает |
| --- | --- |
| [src/app](src/app/README.md) | Вход, приглашения, сессия, маршруты, переключение пространства и общая навигация |
| [src/features](src/features/README.md) | Обзор, точки, ассистент, отчёты, разборы, данные, настройки и первые шаги |
| [src/shared](src/shared/README.md) | API-клиент, типы данных, формы, таблицы, SQL, графики, экспорт и стили |
| [tests](tests/README.md) | Проверки поведения компонентов и сценариев с настоящим API |

Внутри функционального раздела `pages` собирает экран, `components` содержит его формы и карточки, `hooks` — запросы и наблюдение, `model` — преобразования и подписи. Папка появляется, когда у неё есть отдельная ответственность и код. Подключения, показатели, планы и технические обращения объединены разделом `features/data`, но реализованы независимо друг от друга.

## Что важно в поведении

- Период, показатель, область точек, фильтры списков и открытые карточки отражаются в URL. Ссылку можно открыть повторно; сервер заново проверит доступ.
- Сервер рассчитывает показатели и ограничивает данные. Скрытая кнопка не заменяет проверку полномочий API. Технический администратор не получает финансовые данные только потому, что умеет менять подключение.
- Активное задание ассистента продолжает работать после закрытия страницы. Интерфейс получает события и дополнительно опрашивает состояние; отмена выполняется отдельной командой.
- Готовый результат сохраняет свои SQL, период и область. Изменение условий следующего вопроса не меняет уже показанную таблицу. Пересчёт отчёта создаёт новую попытку и сохраняет предыдущую.
- Отсутствие данных, настоящий ноль, ошибка и ограниченная выдача показаны отдельно. Десятичные строки форматируются без потери точности; CSV содержит исходные значения. График визуализирует переданные строки и не пересчитывает бизнес-показатель.
- Черновики форм живут в памяти текущего пространства. Они сохраняются при переходах, но сбрасываются после перезагрузки, выхода или смены пространства. Пароли и токены не записываются в браузерное хранилище.
- Навигация и формы доступны с клавиатуры. На узком экране меню становится выдвижной панелью с управлением фокусом; широкие таблицы прокручиваются внутри своей области.

## Разработка и сборка

Нужен Node.js 24 и зависимости из [package-lock.json](package-lock.json). Команды выполняются из `frontend` одинаково в Windows и Linux:

```text
npm ci
npm run dev
```

Если зависимости уже установлены, достаточно `npm run dev`. Vite открывает сервер разработки на `http://127.0.0.1:5173` и передаёт `/api` в Python API на `http://127.0.0.1:8000`. Backend должен быть запущен отдельно; изменение порта API требует изменения proxy в [vite.config.ts](vite.config.ts).

```text
npm run typecheck
npm test
npm run build
```

`build` проверяет TypeScript и создаёт `dist`. `npm run preview` показывает собранные файлы, но его конфигурация не содержит API proxy: это не замена полному запуску продукта. Общий запуск и контейнеры описаны в [руководстве эксплуатации](../docs/operations/README.md).

Для изменения интерфейса начните с [руководства frontend-разработчика](../docs/development/frontend.md): там собраны маршруты, состояние, работа с API, правила изменения форм, результата и стилей, а также порядок добавления нового раздела.
