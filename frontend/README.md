# Интерфейс «Разбора»

«Разбор» помогает команде сети пройти путь от вопроса о данных до общего решения. Руководитель видит показатели доступных точек, аналитик задаёт смысл расчётов, управляющий отвечает на конкретный вопрос по своей точке. Ассистент превращает обычную формулировку в таблицу; рядом можно открыть SQL, сохранить отчёт и передать отдельный результат в обсуждение.

У ролей общее рабочее пространство и одинаковые понятия. Различаются стартовая страница, доступные действия и область данных. Это позволяет обсуждать один результат, не создавая шесть несовместимых интерфейсов. Пустые данные, настоящий ноль, ограниченная выдача и ошибка показаны как разные состояния.

## Как устроена работа

- **Обзор и точки** показывают серверные показатели, план и сравнение одинаковых точек между периодами. Браузер не суммирует произвольную выдачу агента и не подставляет демонстрационные числа.
- **Ассистент** хранит личные разговоры и явно выбранное основание продолжения. Условия нового вопроса отделены от условий готового результата. Задание остаётся на сервере после закрытия вкладки; остановка — отдельное действие.
- **Отчёты** сохраняют конкретный расчёт. Повторное выполнение SQL создаёт новый запуск, а исходный снимок остаётся доступным.
- **Разборы** связывают точку, наблюдение, прикреплённый результат, адресный вопрос сотруднику, ответ и итог. Личный диалог не публикуется вместе с таблицей.
- **Данные** объединяют подключение PostgreSQL, разрешённые таблицы и поля, определения показателей и планы. Доступ к настройке каждой части проверяется отдельно.
- **Настройки** содержат команду, приглашения, справочник точек, смену пароля и управление сеансами. Приглашённый сотрудник задаёт пароль самостоятельно.

## Код и связи

Приложение написано на React и TypeScript. Vite собирает статические файлы; backend отдаёт их с того же адреса, что и API. React Router управляет страницами, TanStack Query — серверным состоянием, TanStack Table — табличной выдачей, Radix Dialog — модальными окнами и фокусом.

| Часть | Ответственность |
| --- | --- |
| [src/app](src/app/README.md) | Вход, сессия, рабочее пространство, навигация и фильтры URL |
| [src/features](src/features/README.md) | Пользовательские сценарии по разделам |
| [src/shared](src/shared/README.md) | Контракт API, общие элементы, таблица результата, экспорт и стили |
| [tests](tests/README.md) | Проверки точности, границ доступа, сеанса и действий в браузере |

Запросы идут через [client.ts](src/shared/api/client.ts) к [Python API](../backend/API.md). Авторизация использует HttpOnly cookie; изменяющие запросы передают CSRF. Проверки полномочий в браузере управляют интерфейсом, сервер самостоятельно разрешает чтение и изменение данных. При смене пользователя очищается частный кэш; при смене пространства старые запросы отменяются. После отказа в чтении результата его сохранённая копия не остаётся на экране.

Финансовые значения хранятся и форматируются как десятичные строки. В SQL-таблице сохраняется вся переданная точность, округление карточек не использует двоичную арифметику. CSV содержит исходные значения, экранирует формулы и явно называется частичным при ограниченной выдаче.

## Разработка и проверка

Нужен Node.js 24. Установка по `package-lock.json` и команды одинаковы в Windows и Linux:

```text
npm ci
npm run dev
```

Vite перенаправляет `/api` на `http://127.0.0.1:8000`. Для собранного приложения отдельный Node-сервер не нужен: `npm run build` создаёт `dist`, который обслуживает backend. Общий запуск проекта описан в [корневом README](../README_RU.md).

```text
npm run build
npm test
npm run format:check
```

Браузерный тест работает с отдельным реально запущенным экземпляром и тестовым аккаунтом. Параметры и ограничения проверки описаны в [tests/README.md](tests/README.md). Проверка интерфейса без загруженной модели подтверждает обычные операции SaaS, но сама по себе не подтверждает генерацию SQL.
