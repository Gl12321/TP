# Изменения прикладной БД

Миграции переводят существующее пространство на новую структуру без потери пользователей, истории и обсуждений. Они относятся только к PostgreSQL приложения; структура подключённой БД клиента не изменяется.

`0001_workspace` создаёт исходную схему. Последующие версии явно меняют ограничения и таблицы, вместо повторного создания ORM-схемы при каждом запуске. [env.py](env.py) получает URL из команды [bootstrap](../app/bootstrap.py), а не из сохранённого пароля в репозитории.

Применение: `python -m backend.app.bootstrap migrate`. Выполняйте команду до запуска API и worker; общий запуск проекта делает этот шаг отдельно. Перед обновлением рабочего сервиса сохраняйте резервную копию прикладной БД и ключа шифрования источников.

Проверки миграций создают реальную временную SQLite-БД, применяют ревизии и сравнивают итоговую структуру с ORM. Это проверяет переносимость локального режима; поведение PostgreSQL блокировок отдельно проверяется на PostgreSQL, а не выводится из успеха SQLite.
