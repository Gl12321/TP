# Проверки серверных сценариев

Набор защищает границы данных и основные действия пользователя: вход, получение результата, сохранение отчёта, назначение разбора и отмену работы. Вместо отдельных проверок каждого поля используются несколько связанных сценариев с разрешёнными и запрещёнными действиями.

## Как устроен набор

| Файл | Проверяемый контракт |
| --- | --- |
| [test_application.py](test_application.py) | Настоящий ASGI API, сессии и CSRF, доступ к пространству, точкам и источнику, идемпотентность, очередь и аренда задания, отчёты, назначение и закрытие разбора |
| [test_scoped_sql.py](test_scoped_sql.py) | Ограничение строк и колонок, OR и JOIN, связанные параметры, запрет скрытых полей и неподдерживаемого SQL |
| [test_configuration.py](test_configuration.py) | Чтение YAML и окружения, отклонение ошибочных настроек, сохранение паролей, выбор модели worker |
| [test_postgres_integration.py](test_postgres_integration.py) | Настоящие миграции и межпространственные ограничения БД, роль только для чтения, точные суммы, фильтрация обеих сторон JOIN, таймаут и отмена запроса |

Прикладные сценарии создают временную SQLite-БД. Вместо модели используется исполнитель с фиксированным контрактом ответа; сеть и веса для этих проверок не нужны. Проверки грамматики и генератора находятся в [пакете агента](../../packages/sql_agent/tests/README.md).

## Запуск

Из корня проекта в Python-окружении с [зависимостями разработки](../../requirements-dev.txt):

```text
python tools/check.py backend
```

Для одного сценария используйте pytest напрямую:

```text
python -m pytest backend/tests/test_application.py -q -k recipient
```

### PostgreSQL

Для интеграционных проверок задайте `RAZBOR_TEST_DATABASE_URL`: административный URL отдельного локального тестового кластера. Допустимы только `127.0.0.1`, `localhost` и `::1`; роль должна уметь создавать БД, роли и выдавать им права. Без переменной PostgreSQL-сценарии пропускаются.

```text
python tools/check.py postgres
```

Набор создаёт случайную БД `razbor_it_*` и роль `razbor_reader_*`, применяет миграции к новой БД и удаляет только созданные ресурсы после завершения. База из исходного URL служит административным подключением и не мигрируется. Для этих проверок нельзя указывать рабочий кластер организации.

## Что дополнять при изменениях

Изменения доступа проверяйте разрешённым действием и отказом за его границей. Изменения SQL — фактическим результатом и отсутствием чужих строк; изменения миграций — ограничением реальной PostgreSQL-БД. Дополняйте существующий сценарий, если новая проверка относится к тому же контракту, вместо создания дублирующего окружения.

Демонстрационные данные и ручной просмотр интерфейса отделены от проверок: [деморежим](../../docs/demo/README.md). Общие команды и границы автоматической проверки описаны в [руководстве тестирования](../../docs/development/testing.md), устройство сервера — в [руководстве backend](../../docs/development/backend.md).
