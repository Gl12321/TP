# Проверки серверных сценариев

Тесты проверяют поведение продукта через настоящий ASGI API и временную БД: вход, CSRF, роли и области, приглашения, очередь, историю результатов и обсуждения. Они должны ловить утечку данных или неверный переход состояния, а не повторять устройство каждой функции.

[test_application.py](test_application.py) проходит вертикальные сценарии, включая снятие прав до публикации, идемпотентность, смену пароля, повторное использование приглашения и общий доступ к отчёту. Исполнитель модели заменён тестовым адаптером с фиксированным контрактом, поэтому успешный прогон не заявляет качество настоящего GGUF.

[test_scoped_sql.py](test_scoped_sql.py) проверяет защиту строк и полей на запросах с `OR`, соединениями, агрегатами и `*`. PostgreSQL-оператор привязки массива переводится в эквивалентный SQLite-подзапрос только в тестовом исполнителе; полученный AST реально исполняется на данных двух точек. Скрытая колонка, чужая таблица, несколько statements, CTE и подзапросы отклоняются до исполнения.

[test_constraints.py](test_constraints.py) применяет миграции к существующим записям и пытается связать объекты чужих пространств напрямую через БД. [test_configuration.py](test_configuration.py) проверяет выбор той же модели, что выбрал общий запуск, строгие настройки и сохранение пробелов в паролях. Проверка начала HTTP-ответа отдельно подтверждает, что сессия уже записана до отправки cookie браузеру.

Запуск после установки зависимостей: `python -m unittest discover -s backend/tests`. Тесты не скачивают модели, не требуют Docker и не подключаются к чужим БД. Проверки SQL-грамматики и генератора находятся отдельно в [пакете ядра](../../packages/sql_agent/tests/README.md).

Для [нативного PostgreSQL](test_postgres_integration.py) задаётся отдельный `RAZBOR_TEST_DATABASE_URL` к локальному одноразовому кластеру. Нужна роль с CREATEDB и CREATEROLE. Набор создаёт случайную БД `razbor_it_*` и роль `razbor_reader_*`, применяет миграции только к созданной БД и удаляет только эти ресурсы. База из переданного URL не мигрируется. Проверяются реальные права чтения, ограничения колонок и строк, типы значений, отмена и таймаут запроса, освобождение соединения, аренда и конкурирующее завершение. Без этой переменной набор явно пропускается; успех SQLite не выдаётся за проверку поведения PostgreSQL.

Для ручной проверки интерфейса [seed_ui_source.py](seed_ui_source.py) создаёт отдельный источник с двумя точками, выручкой за сентябрь и октябрь и ролью только для чтения. Скрипт использует локальный тестовый кластер из `.runtime/postgres-check/connection.json` и сохраняет тела запросов настройки, ожидаемые суммы и реквизиты подключения в `.runtime/postgres-check/ui-source.json`. Этот файл содержит пароль и остаётся в игнорируемой рабочей директории. Данные не появляются в продукте автоматически: источник, точки, политики, показатель и планы подключаются обычными API-действиями. Поэтому такая проверка проходит тот же путь настройки, что и рабочая организация, а тестовые суммы не подменяют пустое состояние нового пространства.
