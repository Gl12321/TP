# Личный вопрос к данным

Пользователь задаёт вопрос обычными словами и получает таблицу вместе с SQL. Продолжение «а теперь по городам» связывается с выбранным прежним расчётом. Если условий недостаточно, приложение сохраняет просьбу об уточнении, которую можно продолжить новым сообщением.

Модуль отвечает за личную историю и условия запуска. Сам алгоритм построения SQL находится в отдельной [библиотеке sql_agent](../../../packages/sql_agent/README.md).

## Как устроено

[models.py](models.py) хранит диалоги, сообщения и запуски. [service.py](service.py) проверяет права, версии и повторную отправку, затем атомарно создаёт сообщение, запуск и долговечное задание. [api/routes.py](api/routes.py) выдаёт историю, принимает команды и транслирует сохранённые события SSE; входные формы находятся в [api/schemas.py](api/schemas.py).

[engine.py](engine.py) — граница приложения и библиотеки. Он передаёт разрешённый каталог, определения показателей, выбранные точки и период. Основание продолжения ограничено вопросом, SQL и условиями одного выбранного запуска. Строки результата, пароли источников и комментарии коллег в модель не передаются.

## Условия и история

В одном диалоге выполняется один запрос. `version` защищает отправку из устаревшей вкладки; `idempotency_key` возвращает прежний запуск после сетевого повтора. Новый ключ с новой командой создаёт новую попытку. Личный диалог принадлежит автору, сохранение результата в общий отчёт — отдельное действие.

При продолжении отсутствующие условия периода или показателя наследуются от `base_run_id`; явный `null` очищает выбор. Период передаётся обеими границами и включает конечную дату. Область точек задаётся заново; пустой список означает доступные активные точки. Ответ на уточнение использует основание со статусом `needs_input`. Совместимость диалога, источника и основания проверяется сервером.

`run.context` хранит выбранные условия и версии, но не доказывает, что модель правильно выразила их в SQL. Результат отдельно содержит SQL расчёта и фактически исполненный SQL с параметрами серверных ограничений. Эти сведения имеют те же права чтения, что и таблица.

## Выполнение и доступ

[Worker](../worker.py) обрабатывает [задание](../jobs/README.md) независимо от вкладки. Закрытие SSE не отменяет работу; для остановки есть отдельная команда. Пропущенное событие восстанавливается повторным GET запуска. Отзыв доступа прекращает поток и скрывает недоступные результаты, сообщения и связанный заголовок диалога.

Обновление общего [отчёта](../analytics/README.md) использует тот же путь задания, но выполняет сохранённый SQL без новой генерации. Прикрепление результата к [разбору](../collaboration/README.md) не раскрывает личную переписку автора.

Статусы, payload и правила повторной отправки описаны в [API](../../API.md), порядок изменения интеграции — в [руководстве бэкенда](../../../docs/development/backend.md).
