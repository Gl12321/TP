# Источники и разрешённые данные

Профиль источника задаёт, какие данные организации приложение может читать и кому они доступны. Исходная PostgreSQL остаётся у клиента. Сотрудник работает с разрешёнными таблицами, а пароль подключения не передаётся браузеру или языковой модели.

Техническая проблема имеет отдельный путь: сотрудник создаёт обращение по профилю, администратор получает описание и состояние подключения, берёт его в работу и фиксирует решение. Для этого не нужно выдавать администратору доступ к финансовой таблице.

## Как устроено

| Файл | Ответственность |
| --- | --- |
| [models.py](models.py) | Профиль, каталог, политики, обращения и их комментарии |
| [api/connections.py](api/connections.py) | Подключения, проверка источника, выдача каталога, сохранение политик |
| [api/issues.py](api/issues.py) | Создание обращения, обсуждение, назначение и смена статуса |
| [api/schemas.py](api/schemas.py) | Входные формы подключения, политики и обращения |
| [service.py](service.py) | Соединение, инспекция, разрешённый каталог и ограниченный SQL-исполнитель |
| [issues.py](issues.py) | Проверка обращения, адресата и получателей уведомлений |

Соединение использует разрешённый сервером hostname и отдельную роль PostgreSQL. Проверка источника отклоняет административные полномочия и права записи в доступные таблицы выбранных схем; каталог сохраняет колонки, ключи и связи. Список читателей профиля проверяется независимо от роли и области точек.

## Как ограничивается чтение

Администратор выбирает колонки каждой таблицы и поле внешнего кода точки. Общий справочник разрешается явным `shared=true`; факт требует `store_column`, сопоставленного с `Store.code`. Аналитик получает только разрешённый каталог, администратор подключения — каталог для настройки политики.

Перед выполнением SELECT проверяется AST. Каждая таблица заменяется внутренним SELECT разрешённых полей и строк назначенных точек. Коды привязываются параметрами и не становятся SQL-текстом. Фильтрация действует до JOIN и агрегирования; внешний `OR` не расширяет область. Дополнительные ограничения — роль чтения, транзакция `READ ONLY`, таймаут и предел результата.

`ssl_mode=verify-full` проверяет сертификат и имя сервера; `require` шифрует соединение без этих проверок; `disable` отключает TLS. Рабочий профиль следует согласовать с настройкой сервера клиента. Адрес должен входить в `application.source_hosts` либо `APP_SOURCE_HOSTS`; пустой список запрещает подключения.

В API ограничено восемь соединений всего и два на профиль, в worker — два и одно. Ожидание слота — до пяти секунд. Лимиты относятся к процессу. Подробности конфигурации и развёртывания — в [руководстве эксплуатации](../../../docs/operations/configuration.md).

## Версии и история

`catalog_version` отражает снимок структуры, `policy_revision` — разрешённые данные и существенные изменения профиля. Перепроверка метаданных сохраняет доступ к старым результатам. Смена политики, списка читателей или существенных параметров требует нового расчёта; отключение профиля также закрывает чтение результатов. Во время активного задания изменение каталога прерывает работу на прежней структуре.

`reader_ids=null` означает всех участников с `analytics:read`, список — только указанных пользователей, `[]` — отсутствие читателей. Владение пространством не обходит этот список. `sources:manage` позволяет обслуживать профиль и обращения без финансового чтения.

## Технические обращения

Обращение сохраняет состояние источника при создании и показывает текущее состояние отдельно. Статусы: `open`, `in_progress`, `resolved`. Завершение требует текста решения; повторное открытие очищает текущее решение, сохраняя прежнее в истории. Статус обращения сам по себе не исправляет подключение.

Администратор источников видит обращения пространства. Обычный участник — обращения только по доступным ему профилям; отзыв чтения скрывает также соответствующие уведомления. При действующем назначении уведомляются ответственный и автор, без действующего ответственного — доступные администраторы; совершивший действие исключается.

Контракт не принимает автоматическое прикрепление SQL или финансового результата. Для обсуждения цифр предназначены [разборы](../collaboration/README.md). [Аналитика](../analytics/README.md) и [ассистент](../assistant/README.md) используют общий `ScopedExecutor`. HTTP-поля и ошибки описаны в [API](../../API.md).
