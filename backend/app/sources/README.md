# Источники и разрешённые данные

Подключение должно давать приложению ровно те данные, с которыми договорилась работать сеть. Внешняя БД остаётся у клиента; её пароль не попадает в браузер или языковую модель. Профиль источника хранит адрес, роль чтения, выбранные схемы и зашифрованный секрет.

[service.py](service.py) проверяет соединение, отклоняет административную роль и права записи в доступные таблицы, собирает колонки, ключи и связи. В настройке доступа администратор выбирает разрешённые поля и колонку внешнего кода точки. Общий справочник допускается только явным `shared: true`. Каталог аналитика включает только разрешённые поля; технический администратор видит исходный каталог для настройки.

Перед исполнением SELECT проверяется AST с каталогом. Затем каждая таблица заменяется внутренним SELECT, содержащим только разрешённые колонки и строки назначенных точек. Значения кодов привязываются как параметры; они не становятся текстом SQL. Такая подстановка действует до JOIN и агрегирования, поэтому внешние фильтры не расширяют область. Это ограничение приложения дополняется ролью чтения и транзакцией PostgreSQL `READ ONLY`; оно не объявляется политикой RLS самой БД.

На процесс API допускаются восемь одновременных соединений и не более двух к одному источнику; ожидание ограничено пятью секундами. Worker имеет собственный меньший лимит. У запросов есть таймаут, предел строк и размера значений. Возвращаемые ошибки не раскрывают пароль и параметры соединения.

Версия каталога нужна [sql_agent](../../../packages/sql_agent/README.md) для проверки актуальности структуры. Ревизия политики нужна [ассистенту](../assistant/README.md) для доступа к сохранённому результату. Перепроверка метаданных сохраняет историю; изменение разрешённых данных требует нового расчёта. PostgreSQL приложения и PostgreSQL источника используют отдельные подключения и полномочия.
