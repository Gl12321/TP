# Показатели, планы и отчёты

Руководителю нужна воспроизводимая цифра: по каким точкам, за какой период и по какому определению она посчитана. Модуль связывает внешние коды точек с источником, хранит определения показателей и редакции планов, рассчитывает обзор обычным кодом.

Сохранённый отчёт делает конкретный результат доступным коллегам с нужными правами. Он сохраняет основание расчёта и позволяет получить новую версию результата без переписывания предыдущей.

## Как устроено

[models.py](models.py) хранит точки, версии показателей, планы и ссылки на отчёты. [api/routes.py](api/routes.py) проверяет доступ и принимает операции; формы находятся в [api/schemas.py](api/schemas.py). [service.py](service.py) строит SQL обычного обзора, сопоставляет периоды и рассчитывает итоговые значения.

Определение показателя указывает таблицу, ключ точки, поле даты, поле значения и операцию `sum`, `count` или `avg`. Повторное сохранение того же `key` создаёт новую версию с новым идентификатором. План относится к конкретной версии показателя, точке и месяцу; повтор создаёт редакцию. Чтение выполняется через тот же ограниченный [источник](../sources/README.md), что использует ассистент.

## Правила расчёта

- Конец выбранного периода включителен: SQL использует верхнюю границу следующего дня.
- Полный месяц сравнивается с предыдущим календарным месяцем. Блок полных месяцев — с предыдущим блоком той же длины; произвольный диапазон — с предшествующим диапазоном той же длительности в днях.
- Оба периода читаются одним SQL, чтобы изменение источника между двумя запросами не исказило сравнение.
- Сопоставимое изменение использует точки со значением в обоих периодах. Средние агрегируются с весами, а не средним от средних.
- План учитывается за полные месяцы и сравнивается с фактом на общей области. Средние планы разных месяцев не складываются без весов; автоматического распределения месячного плана по дням нет.
- Отсутствие строк отличается от нуля. Наличие строк не доказывает полноту загрузки источника.

Обзор содержит итог, сравнение, точки и группировку по городам. Карточка точки возвращает дневную либо недельную динамику; пропуск остаётся `null`. Денежные значения выдаются decimal-строками. Календарные даты для `timestamptz` определяются часовым поясом сессии источника; отдельного бизнес-часового пояса у пространства пока нет.

## Отчёты и связи

Отчёт ссылается на конкретный успешный запуск и его SQL. Обновление создаёт новое [задание](../jobs/README.md), проверяет сохранённый запрос по текущему каталогу и выполняет его без новой генерации. История сохраняет все попытки, включая ошибки и выполняющиеся запросы; исходный снимок не заменяется.

Читатель должен иметь доступ ко всей области и профилю результата. История обновлений проверяется по каждой попытке. Личный [диалог](../assistant/README.md) автора не становится общим вместе с таблицей.

Из обзора можно создать [разбор](../collaboration/README.md), сохранив исходное измерение: факт, план, определение показателя и выбранные точки. Последующий расчёт добавляется отдельным снимком. Форматы ответов и параметры периодов — в [API](../../API.md), порядок расширения аналитики — в [разработке бэкенда](../../../docs/development/backend.md).
