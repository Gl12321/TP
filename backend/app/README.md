# Прикладные сценарии

Эта директория связывает данные организации с действиями сотрудников: доступом к цифрам, сохранением отчёта, вопросом ответственному и проверкой принятого решения. Здесь находятся правила SaaS. Построение SQL по тексту вынесено в самостоятельную библиотеку и подключается к ним через явный интерфейс.

## Как распределена ответственность

| Модуль | Отвечает за | Связан с |
| --- | --- | --- |
| [access](access/README.md) | Аккаунты, сессии, пространства, назначения и возможности | Все операции получают проверенный `Access` |
| [sources](sources/README.md) | Подключение, каталог, политики строк/полей, чтение SQL, технические обращения | `analytics` и `assistant` используют общий `ScopedExecutor` |
| [analytics](analytics/README.md) | Точки, показатели, планы, обзор и отчёты | Читает источник, передаёт обновление отчёта в очередь |
| [assistant](assistant/README.md) | Диалоги, вопросы, выбранные условия, интеграция `sql_agent` | Создаёт `jobs` и получает каталог от `sources` |
| [collaboration](collaboration/README.md) | Разборы, измерения, комментарии, адресные вопросы, уведомления | Проверяет область и прикреплённые результаты |
| [jobs](jobs/README.md) | Очередь, аренда, отмена, события, публикация | Выполняется отдельным `worker.py` |
| [infrastructure](infrastructure/README.md) | БД, конфигурация, шифрование, HTTP и пагинация | Общие механизмы без правил показателей |

[main.py](main.py) собирает API, обработчики ошибок и раздачу `frontend/dist`. [bootstrap.py](bootstrap.py) применяет миграции до запуска сервиса. [worker.py](worker.py) загружает локальные модели и исполняет задания.

Внутри предметного модуля `api/` содержит маршруты и входные схемы, `models.py` — хранимые сущности, `service.py` — общие операции. Самостоятельные сценарии выделены в `collaboration/measurements.py` и `sources/issues.py`. Маршруты не должны импортировать маршруты соседнего модуля ради бизнес-операции: общее правило размещается в сервисе владельца данных.

## Три пути выполнения

**Обычный обзор:** маршрут проверяет участника и точки → `analytics.service` строит расчёт из определения показателя → `sources.ScopedExecutor` применяет политику и читает источник → API возвращает значения и основание расчёта. LLM не вызывается.

**Вопрос ассистенту:** маршрут сохраняет вопрос и задание → worker захватывает его → `assistant.engine` собирает контракты библиотеки → `sql_agent` строит SQL → ограниченный исполнитель получает таблицу → `jobs` проверяет актуальные права и сохраняет результат. Клиент получает этапы через SSE и восстанавливает состояние через GET запуска.

**Работа команды:** участник сохраняет результат в отчёт или разбор → сервер проверяет всю область прикреплённого факта → адресат получает уведомление → ответ и итог остаются в истории. Комментарии сотрудников не передаются модели.

## Связи с другими частями

[Библиотека агента](../../packages/sql_agent/README.md) не знает пользователей, cookie, ORM приложения или пароли источников. [Фронтенд](../../frontend/README.md) использует [HTTP-контракт](../API.md); изменение кнопки не заменяет серверную проверку права. Структура БД обновляется через [миграции](../migrations/README.md).

Порядок изменения маршрута, сущности, права и SQL-поведения описан в [руководстве по бэкенду](../../docs/development/backend.md).
