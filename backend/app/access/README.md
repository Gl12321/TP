# Участники и доступ

У руководителя, управляющего точки и аналитика разные действия и области данных. Этот модуль превращает назначения в проверяемый сервером контекст доступа. Скрытая кнопка в браузере не является проверкой права; операция выполняет её повторно.

[policy.py](policy.py) описывает шесть ролей и отдельную область точек. `data_access` позволяет администратору обслуживать подключения без просмотра аналитики. Пространство и членство проверяются при каждом запросе; отключённый аккаунт перестаёт участвовать также в фоновых заданиях и потоках событий.

[routes.py](routes.py) отвечает за первоначальную настройку, вход и управление участниками. Сессионный токен хранится в браузере только в HttpOnly cookie, а в БД — его хеш. Изменяющие запросы требуют CSRF-токен. Пароли проверяются scrypt с ограниченным числом одновременных вычислений; попытки входа ограничиваются по аккаунту и адресу.

[account.py](account.py) создаёт дополнительные пространства, одноразовые приглашения на семь дней, меняет пароль и отзывает сессии. Приглашение существующего аккаунта принимается только после входа под соответствующим адресом. При смене пароля все прежние сессии отзываются, текущий браузер получает новую. Первое назначение владельца защищено кодом первоначальной настройки и уникальной записью БД.

Изменения участников увеличивают ревизию доступа. [Задания](../jobs/README.md) проверяют её перед публикацией. [Обсуждения](../collaboration/README.md) разрешают адресата только при доступе ко всей области прикреплённого факта. Журнал успешных изменений хранится в `audit_events`; пароли и тела запросов туда не копируются.
