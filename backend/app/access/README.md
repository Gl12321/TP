# Участники и доступ

У руководителя, управляющего точки и аналитика разные действия и области данных. Модуль превращает назначения в проверяемый сервером контекст доступа. Сотрудник видит только разрешённые данные; скрытая кнопка в браузере не является проверкой права.

## Как устроено

| Файл | Ответственность |
| --- | --- |
| [models.py](models.py) | Аккаунты, пространства, членства, сессии, приглашения и аудит |
| [policy.py](policy.py) | Вычисление возможностей шести ролей и проверка области точек |
| [dependencies.py](dependencies.py) | Сессия HTTP-запроса, CSRF и действующее членство |
| [api/auth.py](api/auth.py) | Первоначальная настройка, вход и управление участниками |
| [api/account.py](api/account.py) | Дополнительные пространства, приглашения, пароль и отзыв сессий |
| [api/schemas.py](api/schemas.py) | Входные формы входа и назначения участника |

`Access` — неизменяемый снимок действующего назначения для операции: пользователь, пространство, ревизия, роль, область и capabilities. Признак владельца добавляет права управления. `data_access=false` удаляет аналитические возможности; администратор по умолчанию обслуживает систему без финансового чтения. Полная матрица — в [руководстве бэкенда](../../../docs/development/backend.md).

## Поведение аккаунта

Сессионный токен находится в HttpOnly cookie, в БД хранится его хеш. Изменяющие запросы требуют CSRF-токен. Пароли проверяются scrypt с ограничением параллельных вычислений; попытки входа учитываются по аккаунту и адресу.

Первое назначение владельца защищено токеном первоначальной настройки и уникальной записью БД. Приглашение одноразовое, действует семь дней. Существующий аккаунт принимает его после входа под приглашённым адресом; для нового аккаунта нужны имя и пароль. Почтового транспорта нет: ссылку передают выбранным организацией способом.

Смена пароля отзывает все прежние сессии и выдаёт текущему браузеру новую. Отдельная операция отзывает остальные сессии. Изменение членства увеличивает его ревизию; отключённый участник перестаёт проходить проверку HTTP, фоновых заданий и SSE.

## Связи и границы

[Задания](../jobs/README.md) проверяют ревизию перед публикацией. [Разборы](../collaboration/README.md) разрешают адресата только при доступе ко всей области факта. [Источники](../sources/README.md) дополнительно проверяют собственный список читателей: даже владелец пространства не обходит его.

`audit_events` хранит успешный изменяющий маршрут и участника. Пароли и тела запросов туда не копируются; это не полный журнал версий полей. Правила добавления capability и HTTP-контракты описаны в [разработке](../../../docs/development/backend.md) и [API](../../API.md).
